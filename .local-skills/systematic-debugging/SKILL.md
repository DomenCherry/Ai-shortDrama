# 系统化调试

## 使用场景

当任务是排查问题而不是实现新功能时使用。

典型场景：

- API 返回错误。
- 前端页面无法加载或请求失败。
- 数据库迁移失败。
- Docker/PostgreSQL 连接失败。
- TypeScript 或 Python 编译失败。
- 用户反馈“不能用”“报错了”“页面没反应”。

## 调试流程

1. 明确现象：记录用户看到的错误、命令输出、页面路径、接口路径。
2. 复现问题：用最小命令或最小操作复现。
3. 缩小范围：判断问题属于前端、后端、数据库、环境、网络或配置。
4. 定位根因：找到具体代码、配置或运行环境原因。
5. 最小修复：只改导致问题的部分。
6. 验证修复：运行能证明问题解决的命令或操作。
7. 说明结果：指出根因、修改点、验证方式。

## 项目常用检查

后端语法：

```bash
.venv/bin/python -m compileall apps/api/app
```

前端类型：

```bash
npm --prefix apps/web run typecheck
```

迁移 SQL：

```bash
npm run db:migrate -- --sql
```

服务健康检查：

```bash
curl http://127.0.0.1:8000/health
```

## 约束

- 不要在没有复现或证据的情况下猜测修复。
- 不要一次性做大范围重构。
- 不要把环境问题误判成业务代码问题。
- 如果 Docker daemon 未运行，应明确这是环境前置条件，不要继续假装数据库可用。
