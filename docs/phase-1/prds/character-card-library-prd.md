# PRD：角色卡库

## 1. 背景

AI 短剧制作工具需要帮助创作者持续产出短剧项目。随着项目数量增加，用户会反复使用相似人物类型、系列角色或已经确认过视觉方向的人物。

如果每个项目都重新设计角色，用户会遇到以下问题：

- 角色设定重复输入，创作效率低。
- 同一系列角色在不同项目中容易出现身份、目标、口吻和视觉描述不一致。
- 已经确认过的人物视觉方向无法沉淀为可复用资产。
- 项目内临时改写角色时，容易误改原始角色设定，影响其他项目。

角色卡库用于把可复用人物设定从具体项目中抽离出来，形成独立资产。角色卡被加载到项目后生成项目内快照副本，项目内修改不会影响角色卡库原始内容。

## 2. 产品目标

- 支持用户独立创建和管理可复用角色卡。
- 支持用户维护角色的文本设定、人物关系、说话方式、视觉描述和参考图。
- 支持角色卡被多个项目加载复用。
- 支持项目内角色快照独立编辑，不回写原始角色卡。
- 为后续人物示意图生成、分集大纲生成和单集剧本生成提供稳定角色上下文。

## 3. 用户与场景

目标用户：

- 个人短剧创作者。
- 希望批量创作同题材、同系列或相似人设短剧的创作者。
- 希望通过 AI 保持角色设定和视觉方向一致的创作者。

核心场景：

- 用户沉淀一个常用女主角色，例如“隐忍复仇型豪门继承人”，后续可加载到多个都市逆袭项目。
- 用户为一个系列短剧维护固定主角和反派，后续不同项目可以复用并局部调整。
- 用户已经生成并确认某个角色示意图，希望角色卡中保留视觉描述和参考图，后续项目继续使用。
- 用户在某个项目里调整角色目标或关系，但不希望影响角色卡库中的原始角色。

## 4. 功能范围

第一期包括：

- 角色卡列表。
- 角色卡新建。
- 角色卡详情查看。
- 角色卡基础信息编辑。
- 角色动机、秘密、关系和剧情功能维护。
- 角色口吻与对白风格维护。
- 角色视觉描述、形象关键词和参考图引用维护。
- 角色卡状态管理。
- 角色卡被项目加载前的预览。
- 角色卡加载到项目后生成项目内快照。
- 项目内角色快照编辑不影响角色卡库原始内容。

第一期不包括：

- 专业角色一致性训练。
- 复杂人物关系图。
- 多角色对话模拟。
- 自动同步角色卡新版本到已加载项目。
- 角色卡版本差异对比。
- 多人共享角色资产。

## 5. 核心流程

### 5.1 创建角色卡

```text
进入角色卡库
 -> 点击新建角色卡
 -> 填写角色基础身份
 -> 选择角色性别
 -> 填写人物目标、动机、秘密和关系
 -> 填写说话方式和对白风格
 -> 填写视觉描述和形象关键词
 -> 可选填写参考图地址或本地路径
 -> 保存角色卡
```

### 5.2 加载角色卡到项目

```text
进入项目创建页或项目工作台
 -> 选择角色卡
 -> 预览角色卡内容
 -> 确认加载
 -> 系统生成项目内角色快照
 -> 后续生成任务读取项目内快照
```

### 5.3 项目内调整角色

```text
进入项目工作台
 -> 打开已加载角色
 -> 修改当前项目需要的目标、关系、口吻或视觉描述
 -> 保存项目内快照
 -> 原始角色卡保持不变
```

## 6. 功能需求

### 6.1 角色卡列表

用户可以查看已创建的角色卡。

列表展示：

- 角色名。
- 性别。
- 角色类型。
- 身份摘要。
- 核心目标。
- 视觉关键词。
- 是否有关联参考图。
- 状态。
- 版本。
- 更新时间。

交互要求：

- 支持新建角色卡。
- 支持进入角色卡详情。
- 支持按角色名搜索。
- 支持按性别、角色类型和状态筛选。
- 支持归档角色卡。

验收标准：

- 用户可以看到已有角色卡。
- 用户可以通过搜索或筛选快速找到目标角色。
- 没有角色卡时，页面应展示空状态和新建入口。

### 6.2 角色卡详情与编辑

用户可以维护角色完整设定。

内容区域：

- 基础身份：角色名、性别、角色类型、身份摘要。
- 人物动机：背景、性格、目标、深层动机。
- 关系与秘密：秘密、冲突点、人物关系。
- 剧情功能：情感弧线、在故事中的功能。
- 口吻风格：说话方式、常用表达。
- 视觉设定：视觉描述、形象关键词、参考图。

基础身份字段规则：

- 性别字段使用 `gender` 保存。
- 性别为必填枚举，只支持男、女两个选项。
- 性别用于后续故事大纲、人物设定、人物示意图和剧本生成中的角色上下文约束。

交互要求：

- 用户可以保存角色卡。
- 用户可以继续编辑已保存角色卡。
- 用户可以归档角色卡。
- 用户可以加载角色卡到项目。

验收标准：

- 用户可以保存完整角色卡。
- 性别为必填字段，只允许选择男或女。
- 必填字段缺失时，系统应阻止保存并给出明确提示。
- 修改核心设定、视觉描述或参考图后，角色卡版本应更新。

### 6.3 视觉设定与参考图

角色卡应支持保存用于人物示意图生成和后续视频一致性参考的视觉信息。

字段建议：

- 年龄感。
- 气质。
- 发型。
- 服装。
- 脸部特征。
- 身形特征。
- 色彩倾向。
- 风格关键词。
- 参考图地址或本地路径。

验收标准：

- 用户可以保存视觉描述和形象关键词。
- 用户可以保存参考图地址或本地路径。
- 视觉描述应避免直接模仿特定现实人物。

### 6.4 状态管理

角色卡状态包括：

- draft：草稿。
- active：可加载。
- archived：已归档。

规则：

- 只有 `active` 角色卡可以被加载到项目。
- `archived` 角色卡不再作为新项目可选项。
- 已归档角色卡不应从历史项目来源记录中删除。
- 第一版使用归档代替硬删除。

验收标准：

- 用户可以将角色卡从草稿改为可加载。
- 用户可以归档角色卡。
- 已归档角色卡不出现在新项目加载候选列表中。

### 6.5 项目加载与快照

用户可以把角色卡加载到项目中。

加载后生成项目内角色快照，快照包含：

- 角色基础设定。
- 人物目标、秘密、关系和口吻。
- 视觉描述和参考图引用。
- 来源角色卡 ID。
- 来源角色卡版本。
- 加载时间。

规则：

- 项目生成任务读取项目内角色快照。
- 项目内修改角色快照，不影响角色卡库原始内容。
- 角色卡库原始内容更新，不自动覆盖项目内快照。
- 同一角色卡可以加载到多个项目。

验收标准：

- 角色卡加载到项目后，项目内存在独立快照。
- 修改项目内快照不会修改原始角色卡。
- 修改原始角色卡不会自动覆盖已加载项目。

### 6.6 加载冲突处理

当项目中已有角色设定，再加载角色卡时，系统需要处理冲突。

第一期规则：

- 用户可以选择“作为新角色加载”。
- 用户可以选择“替换项目内某个角色”。
- 系统不自动合并两个角色。
- 如果角色名重复，系统提示用户确认。

验收标准：

- 角色名重复时，系统不会静默覆盖已有角色。
- 用户明确选择替换后，才更新对应项目内角色快照。
- 作为新角色加载时，已有角色不受影响。

## 8. 生成引用规则

角色卡库原始内容不直接参与生成。项目生成任务应读取项目内角色快照。

生成任务引用规则：

- 整体故事大纲应尽量让已加载角色的目标、秘密和冲突点进入主线。
- 人物设定生成应优先保留项目内角色快照中的性别、核心身份、目标、秘密、关系和视觉描述。
- 人物示意图生成应优先使用项目内角色快照中的视觉描述和形象关键词。
- 分集大纲应围绕角色目标、矛盾和关系推进。
- 单集剧本对白应参考角色口吻和说话方式。

## 9. 用户故事

1. 作为个人短剧创作者，我想创建角色卡，以便沉淀可复用人物设定。
2. 作为个人短剧创作者，我想编辑角色性别、身份、背景和性格，以便让角色设定更完整。
3. 作为个人短剧创作者，我想维护角色目标和动机，以便后续剧情围绕角色行动推进。
4. 作为个人短剧创作者，我想维护角色秘密和冲突点，以便提升短剧反转和悬念。
5. 作为个人短剧创作者，我想维护角色关系说明，以便生成分集和剧本时保持人物关系一致。
6. 作为个人短剧创作者，我想维护角色说话方式，以便剧本对白更符合角色。
7. 作为个人短剧创作者，我想维护视觉描述和形象关键词，以便后续生成人物示意图。
8. 作为个人短剧创作者，我想保存角色参考图，以便后续项目能复用已确认的视觉方向。
9. 作为个人短剧创作者，我想搜索和筛选角色卡，以便快速找到可复用角色。
10. 作为个人短剧创作者，我想把角色卡加载到项目中，以便当前项目基于已有角色继续创作。
11. 作为个人短剧创作者，我想在项目内修改已加载角色，以便适配当前项目。
12. 作为个人短剧创作者，我想项目内修改不影响原始角色卡，以便保护可复用资产。
13. 作为个人短剧创作者，我想同一角色卡可以加载到多个项目，以便复用系列角色。
14. 作为个人短剧创作者，我想归档不再使用的角色卡，以便保持资产库清晰。
15. 作为个人短剧创作者，我想角色名重复时被提醒，以便避免误覆盖项目内已有角色。

## 10. 实现决策

- 角色卡库是项目外资产库，不隶属于单个短剧项目。
- 角色卡加载到项目后采用快照副本模型，不采用实时共享引用模型。
- 项目生成任务读取项目内角色快照，不直接读取角色卡库原始内容。
- 第一版使用归档代替硬删除。
- 第一版不做自动同步、差异对比和多人共享。
- 第一版冲突处理采用显式选择：作为新角色加载或替换项目内角色。
- 视觉信息只保存描述和引用，不在该功能内执行图片生成。

## 11. 测试与验收

测试原则：

- 测试用户可见行为，不测试内部实现细节。
- 重点测试角色卡保存、状态流转、项目加载和快照隔离。
- 重点测试生成引用是否读取项目内快照。

关键验收标准：

- 用户可以创建角色卡。
- 用户可以编辑角色基础信息、动机、秘密、关系、口吻和视觉描述。
- 用户创建或编辑角色卡时必须选择性别，性别仅支持男或女。
- 用户可以保存参考图地址或本地路径。
- 用户可以搜索和筛选角色卡。
- 只有 `active` 角色卡可以被加载到项目。
- 加载到项目后生成项目内快照，并保留来源 ID 和来源版本。
- 同一角色卡可以加载到多个项目。
- 修改项目内角色快照不影响角色卡库原始内容。
- 修改角色卡库原始内容不自动覆盖项目内快照。
- 角色名重复时，系统提示用户确认，不静默覆盖。
- 已归档角色卡不再作为新项目可选项，但历史项目来源仍可追踪。

## 12. 非目标

- 不做角色一致性训练。
- 不做角色图像生成。
- 不做复杂人物关系图。
- 不做多角色对话模拟。
- 不做角色卡版本差异对比。
- 不做自动同步到已加载项目。
- 不做多人协作和权限控制。
