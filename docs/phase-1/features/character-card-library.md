# 功能说明 Spec：角色卡库

## 1. 功能定位

角色卡库用于独立管理可复用人物设定。

它解决的问题是：用户可能会在多个短剧项目中复用某类人物资产、系列角色或已经确认过视觉方向的人物，不希望每次都重新设计人物身份、人设原型、核心欲望、口吻和外观。

角色卡库只管理资产库中的原始角色卡。角色卡被加载到项目后，会生成项目内快照副本；项目内快照的编辑和引用规则见 [创作资产库](./creative-asset-library.md)。

角色卡库不负责塑造具体项目剧情。人物关系、冲突点、反转秘密、情感弧线和剧情功能应在项目角色快照、项目人物设定、故事大纲或世界观中完成。

## 2. 用户目标

- 用户可以创建一个可复用角色卡。
- 用户可以维护角色的基础身份、人物原型、核心欲望、说话方式和视觉描述。
- 用户可以保存角色参考图或人物示意图引用。
- 用户可以在多个项目中加载同一个角色卡。
- 用户可以在项目内改写角色而不影响角色卡库原始内容。

## 3. 功能范围

第一期需要支持：

- 角色卡列表。
- 角色卡新建。
- 角色卡详情查看。
- 角色卡基础信息编辑。
- 角色视觉描述和参考图引用管理。
- 角色卡状态管理。
- 角色卡被项目加载前的预览。

第一期暂不支持：

- 专业角色一致性训练。
- 复杂人物关系图。
- 多角色对话模拟。
- 自动同步角色卡新版本到已加载项目。
- 多人共享角色资产。

## 4. 页面结构

### 4.1 角色卡列表页

列表页用于查看和管理已有角色卡。

展示字段：

- 角色名。
- 人物原型。
- 身份摘要。
- 核心欲望 / 人物执念。
- 视觉关键词。
- 是否有关联参考图。
- 状态。
- 版本。
- 更新时间。

基础操作：

- 新建角色卡。
- 进入角色卡详情。
- 搜索角色名。
- 按人物原型、状态筛选。
- 归档角色卡。

空状态：

- 当没有角色卡时，展示创建入口。
- 空状态文案应引导用户沉淀可复用角色，而不是要求一次性完成所有设定。

### 4.2 角色卡详情页

详情页用于维护一个角色的可复用人物资产。

页面区域：

- 基础身份区。
- 人物资产设定区。
- 口吻与对白风格区。
- 视觉设定区。
- 使用记录区。
- 操作区。

基础操作：

- 保存修改。
- 上传或选择参考图。
- 编辑视觉描述和形象关键词。
- 归档角色卡。
- 加载到项目。

### 4.3 视觉设定区

视觉设定区用于支撑人物示意图生成和后续视频一致性参考。

建议字段：

- 年龄感。
- 气质。
- 发型。
- 服装。
- 脸部特征。
- 身形特征。
- 色彩倾向。
- 风格关键词。
- 参考图上传与图片引用。

视觉描述应避免直接模仿特定现实人物，避免侵犯肖像权或造成误导。

## 5. 字段设计

### 5.1 CharacterCard

表示一个可复用角色卡资产。

字段建议：

- id：唯一标识。
- name：角色名。
- role_type：人物原型，例如复仇者、守护者、操控者、成长型、权力型、治愈型。
- identity：身份摘要。
- background：人物背景。
- personality：性格。
- goal：核心欲望 / 人物执念。
- motivation：旧版兼容字段，新流程不再填写。
- secret：旧版兼容字段，新流程不再填写。
- conflict_points：旧版兼容字段，新流程不再填写。
- relationship_notes：旧版兼容字段，新流程不再填写。
- speech_style：说话方式。
- catchphrases：常用表达或口头禅。
- emotional_arc：旧版兼容字段，新流程不再填写。
- story_function：旧版兼容字段，新流程不再填写。
- visual_description：视觉描述。
- image_keywords：形象关键词。
- reference_image_url：参考图地址。
- reference_local_path：本地参考图路径。
- version：版本号。
- status：状态。
- created_at：创建时间。
- updated_at：更新时间。

## 6. 状态规则

角色卡状态建议：

- draft：草稿。
- active：可加载。
- archived：已归档。

规则：

- 只有 `active` 角色卡可以被加载到项目。
- 已归档角色卡不从历史项目中删除。
- 角色核心设定、视觉描述或参考图发生变化时，应提升版本号。
- 删除已被项目加载过的角色卡风险较高，第一期建议使用归档代替硬删除。

## 7. 项目加载规则

用户在项目创建或项目工作台中选择角色卡后，系统应把当前角色卡内容复制为项目内快照。

快照内容应包括：

- 角色基础设定。
- 人物原型、核心欲望和口吻。
- 视觉描述和参考图引用。
- 来源角色卡 ID。
- 来源角色卡版本。
- 加载时间。

加载后：

- 项目生成任务读取项目内角色快照。
- 用户在项目内修改角色快照，不影响角色卡库原始内容。
- 用户在角色卡库修改原始角色卡，不自动覆盖项目内快照。
- 项目内角色快照可以补充当前项目的剧情目标、人物关系、冲突点、反转秘密、情感弧线和剧情功能，但这些内容不回写原始角色卡。

## 8. 生成引用规则

角色卡库本身不直接参与生成。生成任务应通过项目内快照读取角色内容。

当项目已加载角色卡时：

- 故事大纲应基于项目内角色快照中的人物原型和核心欲望，再生成当前项目的具体剧情目标、关系和冲突。
- 人物设定生成应优先保留角色卡中的核心身份、人物原型、核心欲望和视觉描述。
- 人物示意图生成应优先使用项目内角色快照中的视觉描述和形象关键词。
- 分集大纲应围绕项目内补充的角色目标、矛盾和关系推进。
- 单集剧本中的对白应参考角色口吻和说话方式。

当项目未加载角色卡时：

- 系统仍可根据故事大纲自动生成角色。
- 用户可以后续再加载角色卡，但需要提示已有角色设定可能需要合并或替换。

## 9. 合并与冲突规则

当项目中已经有人物设定，再加载角色卡时，可能出现冲突。

第一期建议采用简单处理：

- 用户可以选择“作为新角色加载”。
- 用户可以选择“替换项目内某个角色”。
- 系统不自动合并两个角色。
- 如果角色名重复，系统提示用户确认。

角色卡加载后，项目内角色快照成为当前项目的依据。后续修改应发生在项目内快照上。

## 10. 验收标准

- 用户可以创建角色卡。
- 用户可以编辑角色基础信息、人物原型、核心欲望、口吻和视觉描述。
- 用户可以上传参考图并保存图片引用。
- 用户可以在列表中搜索和筛选角色卡。
- 用户可以把 `active` 角色卡加载到项目。
- 加载到项目后会生成项目内快照，并保留来源 ID 和来源版本。
- 同一角色卡可以加载到多个项目。
- 一个项目内修改角色快照，不影响其他项目和角色卡库原始内容。
- 角色卡库原始内容更新，不会自动覆盖项目内快照。
- 已归档角色卡不再作为新项目可选项，但历史项目来源仍可追踪。

## 11. 后续扩展

- 支持角色卡版本差异对比。
- 支持从项目内角色另存为新角色卡。
- 支持人物关系图。
- 支持角色对白样例库。
- 支持角色参考图多版本管理。
- 支持基于角色卡的多角色对话测试。
