# 详细设计：创作资产库

## 1. 功能定位

创作资产库用于管理可复用的世界观和角色卡。

第一期中，资产库服务于两个目标：

- 让创作者沉淀可复用的世界观、角色和系列设定。
- 让具体短剧项目可以加载这些资产，并在项目内独立调整，避免修改当前项目时破坏原始资产。

该功能参考 SillyTavern 的“世界书”和“角色卡”思路，但在产品形态上保持短剧创作工作流：用户不需要理解复杂 prompt 插入规则，只需要维护结构化设定，并在项目中选择使用。

世界观库和角色卡库的独立功能说明见：

- [世界观库](./world-book-library.md)
- [角色卡库](./character-card-library.md)

## 2. 核心原则

### 2.1 资产库与项目分离

资产库中的世界观和角色卡是可复用原始内容。项目中的世界观和角色卡是加载后的快照副本。

两者必须分离：

- 修改资产库原始内容，不自动修改已加载到项目中的内容。
- 修改项目内副本，不自动修改资产库原始内容。
- 项目生成任务只读取项目内副本，确保当前项目上下文稳定。

### 2.2 加载不是实时引用

用户将世界观或角色卡加载到项目时，系统复制一份快照到项目中。

快照需要保留：

- 原始资产 ID。
- 原始资产版本。
- 加载时间。
- 项目内当前内容。

这样可以同时满足复用和可控性：资产库负责沉淀，项目快照负责当前项目一致性。

### 2.3 可追踪但不自动覆盖

当资产库原始内容更新后，已加载项目可以显示“来源有新版本”，但系统不能自动覆盖项目内内容。

用户可以选择：

- 保持当前项目快照不变。
- 手动同步来源新版本并确认覆盖范围。
- 将项目内改动另存为新的资产。

第一期可以只实现来源信息展示和手动另存设计，不要求实现复杂差异对比。

## 3. 用户流程

### 3.1 创建世界观资产

```text
进入世界观库
 -> 新建世界观
 -> 填写题材、时代背景、世界规则、组织、地点、风格
 -> 拆分或补充世界观条目
 -> 保存资产
```

### 3.2 创建角色卡资产

```text
进入角色卡库
 -> 新建角色卡
 -> 填写人物身份、背景、目标、秘密、关系、口吻、视觉描述
 -> 可选关联参考图或人物示意图
 -> 保存资产
```

### 3.3 项目加载资产

```text
创建项目或进入项目工作台
 -> 选择已有世界观
 -> 选择已有角色卡
 -> 加载到项目
 -> 系统生成项目内快照
 -> 用户按当前项目需要编辑快照
```

### 3.4 基于项目快照生成内容

```text
项目内世界观快照 + 项目内角色卡快照 + 项目基础信息
 -> 生成选题策划
 -> 生成整体故事大纲
 -> 生成人物设定
 -> 生成分集大纲
 -> 生成单集剧本
```

## 4. 功能范围

第一期需要支持：

- 创建、编辑、查看世界观资产。
- 创建、编辑、查看世界观条目。
- 创建、编辑、查看角色卡资产。
- 在项目创建或项目工作台中加载世界观和角色卡。
- 在项目中查看和编辑已加载的世界观快照。
- 在项目中查看和编辑已加载的角色卡快照。
- 在生成故事大纲、人物设定、分集大纲和剧本时引用项目快照。
- Markdown 导出中包含项目当前使用的世界观和角色卡，并标注来源。

第一期可以暂不实现：

- 多人共享资产库。
- 复杂版本差异对比。
- 自动同步资产库新版本。
- 复杂关键词触发和 prompt 插入位置配置。
- 可视化人物关系图。

表示可复用世界观资产。

建议字段：

- id
- name
- genre
- era_background
- world_rules
- organizations
- locations
- social_structure
- taboo_or_constraints
- tone_style
- version
- status
- created_at
- updated_at

建议字段：

- updated_at

## 6. 页面与交互

### 6.1 世界观库页面

页面用于管理可复用世界观。

详细功能说明见 [世界观库](./world-book-library.md)。

基础能力：

- 查看世界观列表。
- 新建世界观。
- 编辑世界观基础信息。
- 管理世界观条目。
- 停用或归档世界观。

列表建议展示：

- 名称。
- 题材。
- 风格。
- 条目数量。
- 版本。
- 更新时间。

### 6.2 角色卡库页面

页面用于管理可复用角色。

详细功能说明见 [角色卡库](./character-card-library.md)。

基础能力：

- 查看角色卡列表。
- 新建角色卡。
- 编辑角色卡基础设定。
- 管理视觉描述和参考图。
- 停用或归档角色卡。

列表建议展示：

- 角色名。
- 角色类型。
- 身份。
- 视觉关键词。
- 版本。
- 更新时间。

### 6.3 项目资产加载区

项目创建页或项目工作台中应提供资产加载入口。

基础能力：

- 选择世界观资产。
- 选择一个或多个角色卡资产。
- 加载为项目快照。
- 查看来源名称和来源版本。
- 编辑项目内副本。
- 从项目中移除未使用副本。

## 7. 生成上下文规则

生成任务组装上下文时，应优先使用项目内快照。

优先级建议：

1. 用户在当前生成表单中输入的临时要求。
2. 项目内已确认内容，例如最新故事大纲、人物设定、分集大纲。
3. 项目内世界观和角色卡快照。
4. 项目基础信息。
5. 资产库原始内容。

正常情况下，第 5 项不直接进入生成上下文。只有在项目尚未加载快照，但用户明确选择直接引用资产库内容时，才可读取原始资产并先生成快照。

## 8. 导出规则

Markdown 导出应包含：

- 当前项目使用的世界观快照。
- 当前项目使用的角色卡快照。
- 每个快照的来源资产名称。
- 每个快照的来源版本。
- 项目内是否经过编辑。
- 已确认人物示意图引用。

导出内容应以项目当前状态为准，不直接导出资产库最新版本。

## 9. 验收标准

- 用户可以创建世界观资产。
- 用户可以创建角色卡资产。
- 用户可以把世界观资产加载到项目中。
- 用户可以把角色卡资产加载到项目中。
- 同一个世界观资产加载到两个项目后，两个项目内修改互不影响。
- 同一个角色卡资产加载到两个项目后，两个项目内修改互不影响。
- 修改项目内快照不会改变资产库原始内容。
- 修改资产库原始内容不会自动覆盖项目内快照。
- 整体故事大纲生成应能引用项目内世界观和角色卡快照。
- 人物设定生成应能引用项目内角色卡快照。
- Markdown 导出应包含项目当前使用的世界观和角色卡，并标注来源。

## 10. 实现顺序建议

1. 先实现资产库文档与数据模型设计。
2. 再实现世界观和角色卡基础 CRUD。
3. 再实现项目加载资产并生成快照。
4. 再让故事大纲和人物设定生成读取项目快照。
5. 最后补充导出和来源追踪展示。
