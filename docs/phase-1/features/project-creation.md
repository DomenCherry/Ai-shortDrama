# 详细设计：项目创建与时长配置

## 1. 功能定位

“项目创建与时长配置”是第一期的入口功能。它负责让用户创建一个短剧项目，并在项目开始时明确短剧的基础创作约束，包括题材、平台、集数、单集时长和总时长。

该功能的核心价值是：

- 让用户把一个短剧想法沉淀为可管理的项目。
- 在生成任何 AI 内容前，先确定短剧体量。
- 防止项目规模失控，确保后续选题、故事大纲、人物、分集和剧本生成都围绕同一套项目约束进行。

## 2. 目标用户

核心用户是个人短剧创作者。

用户通常只有一个初步想法，例如“都市逆袭爽剧”或“古装重生复仇”，但还没有完整项目结构。项目创建页需要帮助用户快速录入基本信息，而不是要求用户一次性填完所有专业设定。

## 3. 功能目标

用户完成该功能后，系统应获得一个合法、可保存、可继续生成内容的短剧项目。

必须达成：

- 用户可以创建新项目。
- 用户可以录入创意描述和基础信息。
- 用户可以设置集数和单集时长。
- 系统自动计算总时长。
- 系统强校验单集时长和总时长。
- 合法项目可以保存。
- 非法项目不能保存，也不能进入后续 AI 生成流程。
- 用户后续可以返回并编辑项目基础信息。

## 4. 页面设计

### 4.1 项目列表页

项目列表页用于查看已有项目，并创建新项目。

核心元素：

- 页面标题：我的短剧项目。
- 创建项目按钮。
- 项目列表。

项目卡片展示字段：

- 项目名称。
- 题材类型。
- 目标平台。
- 集数。
- 单集时长。
- 总时长。
- 当前进度。
- 更新时间。

空状态：

- 当没有任何项目时，展示空状态提示。
- 提供明显的创建项目入口。

核心操作：

- 创建项目。
- 进入项目工作台。
- 编辑项目基础信息。

### 4.2 项目创建页

项目创建页用于录入新项目基础信息。

页面结构建议：

```text
项目创建页
├── 基础信息
│   ├── 项目名称
│   ├── 创意描述
│   ├── 目标平台
│   ├── 题材类型
│   ├── 目标受众
│   └── 内容风格
├── 时长配置
│   ├── 集数
│   ├── 单集时长
│   └── 总时长预览
├── 备注
└── 操作区
    ├── 取消
    └── 创建项目
```

页面原则：

- 创意描述是最重要的输入，应给较大输入区域。
- 集数和单集时长应靠近展示，并实时计算总时长。
- 时长错误应在用户输入后即时显示。
- 创建按钮在非法状态下禁用，或点击后显示明确错误。

### 4.3 项目基础信息编辑入口

用户进入项目工作台后，应能编辑项目基础信息。

编辑入口建议放在项目概览区域。

编辑行为：

- 修改项目名称、目标平台、题材、目标受众、内容风格、备注时，可以直接保存。
- 修改集数或单集时长时，必须重新进行时长校验。
- 如果项目已经生成后续内容，修改集数或单集时长应提示用户：后续分集大纲和剧本可能需要重新生成。

## 5. 字段设计

### 5.1 Project 字段

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| id | string | 是 | 自动生成 | 项目唯一标识 |
| title | string | 否 | 根据创意自动生成或“未命名短剧” | 项目名称 |
| idea | string | 是 | 无 | 创意描述 |
| target_platform | string | 否 | 抖音 | 目标平台，第一期先允许文本输入 |
| genre | string | 否 | 无 | 题材类型 |
| episode_count | integer | 是 | 20 | 集数 |
| episode_duration | number | 是 | 1 | 单集时长，单位分钟 |
| total_duration | number | 是 | 自动计算 | 总时长，单位分钟 |
| target_audience | string | 否 | 无 | 目标受众 |
| style | string | 否 | 无 | 内容风格 |
| remark | string | 否 | 无 | 备注 |
| status | string | 是 | draft | 项目状态 |
| created_at | datetime | 是 | 自动生成 | 创建时间 |
| updated_at | datetime | 是 | 自动更新 | 更新时间 |

### 5.2 字段说明

项目名称：

- 用户可以手动输入。
- 如果用户未输入，系统可以先保存为“未命名短剧”。
- 后续选题策划生成后，用户可以从剧名候选中选择一个作为项目名称。

创意描述：

- 必填。
- 用于后续选题策划生成。
- 建议最少 10 个中文字符。
- 为空时不能创建项目。

目标平台：

- 第一期先使用文本输入或简单选项。
- 推荐默认值为“抖音”。
- 后续可以扩展为抖音、快手、小红书、视频号、B 站等枚举。

题材类型：

- 第一期可以使用文本输入。
- 可提示示例：都市逆袭、古装重生、豪门恩怨、悬疑反转、甜宠、复仇爽剧。

集数：

- 必填。
- 必须为正整数。
- 默认值为 20。
- 不单独限制最大集数，但必须满足总时长不超过 240 分钟。

单集时长：

- 必填。
- 单位为分钟。
- 必须大于 0。
- 必须小于或等于 2。
- 默认值为 1。
- 支持小数，例如 0.5 表示 30 秒，1.5 表示 90 秒。

总时长：

- 由系统实时计算。
- 不允许用户直接编辑。
- 计算公式：`total_duration = episode_count * episode_duration`。
- 必须大于 0 且小于或等于 240 分钟。

项目状态：

- `draft`：刚创建，尚未生成选题策划。
- `planning`：已进入选题策划或整体故事设计。
- `writing`：已进入分集大纲或剧本阶段。
- 第一期可以只实现 `draft`，但数据结构预留后续状态。

## 6. 校验规则

### 6.1 必填校验

以下字段必须满足：

- 创意描述不能为空。
- 集数不能为空。
- 单集时长不能为空。

### 6.2 类型校验

集数：

- 必须是整数。
- 必须大于 0。

单集时长：

- 必须是数字。
- 必须大于 0。
- 允许小数。

### 6.3 范围校验

单集时长：

```text
0 < episode_duration <= 2
```

总时长：

```text
0 < episode_count * episode_duration <= 240
```

### 6.4 强校验策略

当项目不满足时长规则时：

- 禁止保存项目。
- 禁止进入后续 AI 生成流程。
- 在创建页或编辑页展示明确错误。

系统不自动修改用户输入的集数或时长。

### 6.5 错误提示

| 场景 | 提示文案 |
| --- | --- |
| 创意描述为空 | 请先输入短剧创意描述 |
| 集数为空 | 请填写短剧集数 |
| 集数不是正整数 | 集数必须是大于 0 的整数 |
| 单集时长为空 | 请填写单集时长 |
| 单集时长小于或等于 0 | 单集时长必须大于 0 分钟 |
| 单集时长超过 2 分钟 | 单集时长不能超过 2 分钟 |
| 总时长超过 240 分钟 | 总时长不能超过 240 分钟，请减少集数或单集时长 |

## 7. 交互流程

### 7.1 创建项目流程

```text
用户进入项目列表页
 -> 点击创建项目
 -> 进入项目创建页
 -> 输入创意描述
 -> 填写或使用默认集数
 -> 填写或使用默认单集时长
 -> 系统实时计算总时长
 -> 系统执行字段校验
 -> 用户点击创建项目
 -> 校验通过
 -> 保存项目
 -> 进入项目工作台
```

### 7.2 创建失败流程

```text
用户点击创建项目
 -> 系统发现必填项为空或时长超限
 -> 阻止保存
 -> 显示具体错误提示
 -> 用户修改输入
 -> 再次提交
```

### 7.3 编辑项目基础信息流程

```text
用户进入项目工作台
 -> 点击编辑项目信息
 -> 修改基础字段
 -> 系统重新计算总时长
 -> 系统执行校验
 -> 校验通过后保存
```

如果修改集数或单集时长，且项目已经生成分集大纲或剧本，系统应提示：

```text
修改集数或单集时长可能影响已生成的分集大纲和剧本，保存后建议重新检查或重新生成相关内容。
```

## 8. 状态与边界情况

### 8.1 空项目列表

当没有项目时：

- 展示空状态。
- 引导用户创建第一个短剧项目。

### 8.2 未命名项目

当用户未填写项目名称：

- 系统保存为“未命名短剧”。
- 后续用户可以编辑。
- 后续选题策划生成剧名候选后，用户可以选择剧名替换项目名称。

### 8.3 小数时长

单集时长允许小数。

示例：

- `0.5` 表示 30 秒。
- `1.5` 表示 90 秒。

展示时建议同时显示分钟和秒：

```text
单集 1.5 分钟，约 90 秒
```

### 8.4 边界值

合法边界：

- 1 集，每集 0.1 分钟。
- 120 集，每集 2 分钟，总时长 240 分钟。
- 240 集，每集 1 分钟，总时长 240 分钟。

非法边界：

- 0 集。
- -1 集。
- 每集 0 分钟。
- 每集 2.01 分钟。
- 121 集，每集 2 分钟。

## 9. 后续模块依赖

项目创建成功后，后续模块都应引用 Project 中的基础信息。

选题策划生成依赖：

- 创意描述。
- 目标平台。
- 题材类型。
- 集数。
- 单集时长。
- 总时长。
- 目标受众。
- 内容风格。

整体故事大纲生成依赖：

- 项目基础信息。
- 选题策划。
- 总时长限制。

分集大纲生成依赖：

- 集数。
- 单集时长。
- 总时长。
- 整体故事大纲。
- 人物设定。

单集剧本生成依赖：

- 单集时长。
- 当前集数大纲。
- 人物设定。
- 整体故事大纲。

## 10. 导出要求

Markdown 导出中需要包含项目基础信息。

导出格式建议：

```markdown
## 项目基础信息

- 项目名称：xxx
- 创意描述：xxx
- 目标平台：抖音
- 题材类型：都市逆袭
- 集数：20 集
- 单集时长：1 分钟
- 总时长：20 分钟
- 目标受众：xxx
- 内容风格：xxx
- 备注：xxx
```

## 11. 验收用例

### 11.1 正常创建项目

输入：

- 创意描述：都市逆袭爽剧，女主被丈夫背叛后发现自己是豪门继承人。
- 集数：20。
- 单集时长：1。

预期：

- 总时长显示为 20 分钟。
- 项目保存成功。
- 用户进入项目工作台。

### 11.2 总时长等于上限

输入：

- 集数：120。
- 单集时长：2。

预期：

- 总时长显示为 240 分钟。
- 项目允许保存。

### 11.3 总时长超过上限

输入：

- 集数：121。
- 单集时长：2。

预期：

- 总时长显示为 242 分钟。
- 项目不允许保存。
- 显示提示：总时长不能超过 240 分钟，请减少集数或单集时长。

### 11.4 单集时长超过上限

输入：

- 集数：20。
- 单集时长：2.5。

预期：

- 项目不允许保存。
- 显示提示：单集时长不能超过 2 分钟。

### 11.5 集数非法

输入：

- 集数：0。
- 单集时长：1。

预期：

- 项目不允许保存。
- 显示提示：集数必须是大于 0 的整数。

### 11.6 创意描述为空

输入：

- 创意描述为空。
- 集数：20。
- 单集时长：1。

预期：

- 项目不允许保存。
- 显示提示：请先输入短剧创意描述。

### 11.7 小数时长

输入：

- 集数：30。
- 单集时长：1.5。

预期：

- 总时长显示为 45 分钟。
- 单集时长可显示为 1.5 分钟，约 90 秒。
- 项目允许保存。

## 12. 实现建议

第一期可以先将该功能实现为单用户项目管理能力。

建议优先级：

1. 项目列表页。
2. 项目创建页。
3. 项目基础字段保存。
4. 时长实时计算。
5. 时长强校验。
6. 项目基础信息编辑。
7. Markdown 导出中的基础信息部分。

不要在该功能中提前实现：

- 账号系统。
- 团队权限。
- 复杂平台枚举管理。
- 自动推荐最佳集数。
- 自动修正用户输入时长。
