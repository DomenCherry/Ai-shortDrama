# 第一期 PRD：短剧故事策划、人物确认与剧本工作台

## 1. 文档信息

- 产品名称：AI 短剧创作工作台
- 阶段名称：第一期，短剧故事策划、人物确认与剧本工作台
- 文档版本：v0.5
- 文档状态：草案
- 目标用户：个人短剧创作者
- 核心目标：帮助创作者从一个短剧想法出发，沉淀可编辑、可保存、可检查的短剧项目资料，并逐步扩展到 AI 生成、人物示意图和 Markdown 导出能力。

版本说明：

- v0.3 按当前已实现的项目工作台反向扩充 PRD。
- v0.4 调整项目工作台信息架构：进入工作台后按“项目资料 / 资产、故事文本、短剧制作”组织内容，并明确短剧制作阶段只能沿用上游世界观、角色和故事文本。
- v0.5 补充分集正文创作工作台：故事文本从整体大纲、分集大纲继续延伸到单集故事正文，并引入正文创作、润色、摘要、钩子、质检、角色 / 设定 / 文风 / 灵感参考面板。
- 第一阶段先交付“项目工作台 v1”：项目设定、世界观与角色快照、整体故事大纲、分集大纲、单集故事正文、剧本、分镜与文案的人工编辑和保存骨架。
- AI 生成、内容重新生成、项目内资产副本编辑、分集正文创作工作台和 Markdown 导出仍保留为第一期后续子阶段能力，不作为项目工作台 v1 的已完成功能。

## 2. 背景

本项目的长期目标是帮助个人创作者独立完成短剧内容生产，并将作品发布到线上平台。

完整短剧制作链路包括选题、整体故事设计、人物设定、人物形象确认、分集大纲、单集故事正文、剧本、分镜、素材、配音、字幕、剪辑和发布。第一期不追求完成整个链路，而是优先解决最前置、最影响后续质量的部分：短剧故事策划、人物确认、单集故事正文创作、剧本生成，以及能承接后续分镜和发布文案的项目工作台结构。

第一期完成后，创作者应能够把一个模糊的短剧想法，转化为一套结构化项目资料、可读故事文本和短剧制作文本。项目工作台 v1 先支持人工维护项目设定、已加载世界观与角色、整体故事大纲、分集大纲、单集故事正文、剧本、分镜和文案；工作台信息架构应区分“项目资料 / 资产”“故事文本”“短剧制作”，避免用户在短剧制作阶段随意修改世界观和角色导致前后矛盾。后续子阶段再补齐 AI 生成、分集正文创作工作台、人物示意图和 Markdown 导出。

## 3. 问题定义

个人创作者在制作短剧时，通常会遇到以下问题：

- 有题材想法，但难以快速判断故事卖点是否清晰。
- 不知道如何设计适合短剧的强钩子、强冲突和反转。
- 缺少整体故事脉络，容易只写出单集桥段，而不是一部完整短剧。
- 短剧集数和单集时长缺少约束，容易导致整体体量失控。
- 人物设定容易单薄，人物关系和秘密不够支撑多集剧情。
- 缺少角色视觉参考，后续进入 AI 视频生成时容易出现人物不一致。
- 分集结构难以规划，容易出现节奏拖沓或中途断裂。
- 单集故事正文缺少集中创作界面，用户需要同时查看上游大纲参考、前文参考、世界观、角色和灵感，容易在多份资料之间来回切换。
- 剧本创作耗时长，且不容易符合短视频平台的节奏。
- 创作资料分散在不同文档中，不方便继续修改、复用和导出。

第一期要解决的核心问题是：

> 如何让个人创作者快速完成一部短剧从创意到可打磨剧本、可确认人物形象的前期生产闭环。

## 4. 产品目标

### 4.1 业务目标

- 帮助创作者在较短时间内完成一个短剧项目的策划草稿。
- 降低短剧前期创作门槛，让非专业编剧也能开始搭建故事。
- 在剧本生成前先沉淀整体故事脉络，减少后续剧情跑偏。
- 在人物生成后提供示意图，方便创作者确认角色形象，并为后续视频生成提供一致性参考。
- 为后续分镜、配音、字幕、视觉素材和发布流程打基础。

### 4.2 用户目标

- 用户可以创建一个短剧项目并记录基础信息。
- 用户可以手动调整短剧集数、单集时长和总时长。
- 用户可以从一个想法生成多个可选的短剧方向。
- 用户可以生成整体故事大纲与剧情脉络。
- 用户可以在“故事文本”入口下维护完整故事文本，包括整体故事大纲、分集大纲和每集单集故事正文，形成可读的故事 / 小说化文本。
- 用户可以在单集故事正文创作工作台中查看分集列表、上游大纲参考、正文编辑区、正文元信息、前文参考、世界观、角色、设定、文风和灵感参考。
- 用户可以对单集故事正文执行 AI 正文创作、续写、润色、撤销润色、摘要和一致性质检。
- 用户可以生成清晰的人物设定和人物关系。
- 用户可以为主要人物生成示意图并确认角色形象。
- 用户可以生成完整分集大纲。
- 用户可以生成至少一集完整剧本。
- 用户可以在“短剧制作”入口下把每集单集故事正文转成视频生产所需文本，包括单集脚本、分镜、字幕、传播点和发布文案。
- 用户可以人工维护单集故事正文、分镜镜头和发布文案，为后续制作资料工作台预留结构化输入。
- 用户可以对生成内容进行人工编辑和重新生成。
- 用户可以导出项目文本资料和人物示意图引用。

### 4.3 成功指标

- 用户可以在 10 分钟内生成一个短剧项目草稿。
- 用户可以从创意输入完成到整体故事大纲、人物设定、人物示意图和至少一集剧本生成。
- 用户会对 AI 生成内容进行修改或重新生成，而不是只查看结果。
- 用户可以确认至少 1 个主要人物的示意图。
- 用户可以导出 Markdown 文件用于后续创作或备份。
- 用户愿意基于第一期工具继续制作真实短剧项目。

## 5. 用户画像

### 5.1 核心用户：个人短剧创作者

用户特点：

- 希望自己制作短剧并发布到线上平台。
- 可能具备短视频经验，但未必具备专业编剧能力。
- 更关心能否快速产出内容，而不是复杂团队协作。
- 愿意使用 AI 作为创作助手，但希望保留最终修改权。
- 计划后续使用 AI 图片或 AI 视频工具制作素材，因此需要较早确认角色视觉形象。

核心诉求：

- 快速把想法变成故事。
- 快速获得整体故事脉络、分集大纲、单集故事正文和单集剧本。
- 能够先完成可读故事文本，再把每集故事转成短剧制作文本。
- 能够控制短剧长度和单集时长。
- 能够确认主要人物的视觉方向。
- 能够反复调整内容方向。
- 输出结果能直接进入后续分镜和制作流程。
- 短剧制作阶段应沿用已确认或已保存的世界观、角色和故事文本，避免为了某一集脚本或分镜临时改设定导致前后矛盾。
- 在 AI 生成能力尚未接入时，也能先用人工编辑方式维护大纲、分集、剧本、分镜和文案。

## 6. 使用场景

### 6.1 从零开始创建短剧项目

用户只有一个模糊想法，例如“都市逆袭爽剧，女主被丈夫背叛后发现自己是豪门继承人”。用户希望系统帮助其扩展为完整短剧项目。

### 6.2 控制短剧整体体量

用户希望手动调整短剧集数和每集时长，但系统需要确保单集不超过 2 分钟，总时长不超过 240 分钟，避免后续制作规模失控。

### 6.3 快速生成多个选题方向

用户不确定哪个故事方向更适合发布，希望系统围绕同一题材生成多个剧名、卖点、冲突和爽点方向，方便选择。

### 6.4 复用已有世界观和角色卡

用户已经沉淀了一套世界观或几个常用角色，希望可以在多个短剧项目中复用，而不是每次从零重新输入。用户可以先在资产库中维护世界观和角色卡，再选择加载到具体项目中。

加载到项目后的世界观和角色卡应成为项目内可编辑副本。用户在项目中修改这些内容时，不应直接修改资产库原始内容。

### 6.5 进入项目工作台并选择创作入口

用户进入项目工作台后，首先应理解当前项目分为三类工作区域：

- 项目资料 / 资产：维护基础信息、世界观和角色，作为整个项目的公共上下文。
- 故事文本：把项目写成完整故事，包含整体故事大纲、分集大纲和每集单集故事正文，目标是形成可读的故事 / 小说化文本。
- 短剧制作：把每集单集故事正文转换成视频生产所需文本，包括单集脚本、分镜、字幕和平台发布文案。

短剧制作阶段只能沿用项目资料 / 资产和故事文本中的世界观、角色、整体故事大纲、分集大纲和每集单集故事正文，不提供直接修改世界观或角色的入口。如需调整世界观或角色，用户必须回到项目资料 / 资产或故事文本上游阶段修改，系统再提示下游内容需要检查。

### 6.6 生成整体故事大纲与剧情脉络

用户希望系统先搭建整部短剧的故事骨架，包括故事背景、主线目标、核心矛盾、阶段性反转、情绪曲线、伏笔和结局方向，再继续生成人物与分集。

整体故事大纲是全剧级骨架，不承担分集剧情、单集故事正文或短剧脚本的职责。字段应按三层理解：故事核心层定义故事讲什么、为何开始、最终走向哪里；结构规划层定义全剧阶段、转折、情绪和伏笔；执行辅助层定义节奏、容量和补充约束。分集标题、开场钩子、本集冲突、关键反转和结尾悬念应进入分集大纲；小说化正文应进入单集故事正文；脚本、分镜、字幕、传播点和发布文案应进入短剧制作。

故事大纲应提供三种创作入口：用户手动编辑正式大纲；用户通过【AI提取】从参考故事抽取去具体化结构；用户通过【AI协助】进入对话式创作界面，由 AI 逐步询问并实时补全故事大纲字段草稿。AI 协助创作的完成门槛为故事核心层和结构规划层字段完整，执行辅助层可以由 AI 给出建议但不阻塞完成。AI 协助过程不自动写入正式大纲，用户确认保存后才触发下游内容 `needs_review`。

### 6.7 上传参考故事并抽取叙事结构

用户希望上传或粘贴一个参考故事文本，让系统抽取其中的高层叙事结构、冲突模型、阶段节奏和结局模式，作为当前项目故事大纲的参考框架。抽取结果应完成去具体化处理，不出现参考故事中的具体角色、地名、组织名、专有设定、经典桥段、对白或原文表达。

### 6.8 生成角色和人物关系

用户希望系统自动设计主角、反派、配角、人物目标、人物秘密和人物关系，为后续剧情提供支撑。

### 6.9 生成人物示意图

用户希望在文字人物设定后看到角色示意图，用于确认人物年龄、气质、服装、发型、脸部特征和整体风格，并作为后续视频生成的人物一致性参考素材。

### 6.10 规划完整分集大纲

用户希望系统根据选题、整体故事大纲和人物设定，生成完整分集结构，每集都有钩子、冲突、反转和悬念。

### 6.11 创作单集故事正文

用户希望在故事文本入口中选择某一集，进入类似写作工作台的界面：左侧选择分集，中间编辑单集故事正文，右侧查看世界观、角色、设定、文风 / 参考资料和灵感。用户可以基于本集大纲生成或续写正文，也可以对已写正文进行 AI 润色、撤销润色、摘要和一致性质检。该正文是可读的故事 / 小说化文本，不是短剧脚本。

### 6.12 生成并改写单集剧本

用户希望系统基于某一集单集故事正文生成完整剧本，并支持继续改写，例如增强冲突、缩短对白、提高爽感或改成更口语化。

### 6.13 维护分镜与发布文案

用户希望在单集剧本完成后，继续把剧本拆成可制作的镜头描述、画面提示词、对白或旁白，并维护平台标题、简介、字幕和发布文案。项目工作台 v1 先支持人工编辑和保存这些内容，AI 分镜生成、分镜图生成、配音和字幕文件生成放到后续阶段。

### 6.14 导出项目文本

用户希望把当前项目内容导出为 Markdown 文件，用于后续编辑、备份或交给其他工具继续处理。

## 9. 模块地图与边界

以下模块的详细字段定义、校验规则、用户故事和验收标准见各模块 PRD。

### 9.1 模型 API 配置与连通性测试

用户配置文本和图片生成模型 API，并测试接口可用性。详细设计见 [模型 API 配置](./module-prds/model-api-settings.md)。

### 9.2 创作资产库

世界观和角色卡资产独立管理，项目加载后生成快照副本。架构总则见 [创作资产库](./module-prds/creative-asset-library.md)，子模块见 [世界观库](./module-prds/world-book-library.md) 和 [角色卡库](./module-prds/character-card-library.md)。

### 9.3 项目管理

项目创建、时长配置和列表管理。详细设计见 [项目管理](./module-prds/project-management.md)。

### 9.4 项目工作台

工作台三类入口、内容状态机（draft/confirmed/needs_review）、人工编辑保存和上下游一致性约束。三类入口为：项目资料 / 资产、故事文本、短剧制作。详细设计见 [项目工作台](./module-prds/project-workbench.md)。

### 9.5 选题策划生成（未实现）

AI 生成剧名候选、一句话故事、卖点、冲突和钩子。占位规格见 [选题策划](./module-prds/topic-planning.md)。

### 9.6 整体故事大纲（未实现）

AI 生成故事骨架、起承转合和剧情脉络，并支持从参考故事中抽取去具体化的高层叙事结构，以及通过对话式 AI 协助逐步补全故事大纲字段。详细规格见 [故事大纲](./module-prds/story-outline.md)。

### 9.7 人物设定（未实现）

AI 生成主角、反派和配角设定。占位规格见 [人物设定](./module-prds/character-design.md)。

### 9.8 人物示意图（未实现）

AI 生成角色视觉参考图。占位规格见 [人物示意图](./module-prds/character-image.md)。

### 9.9 分集大纲与单集故事正文创作（未实现）

AI 生成完整分集结构，并提供单集故事正文创作工作台，用于生成、续写、润色、摘要和一致性质检。钩子提取归入短剧制作。详细规格见 [分集大纲](./module-prds/episode-outline.md)。

### 9.10 单集剧本（未实现）

AI 基于单集故事正文生成短剧脚本并支持改写。占位规格见 [单集剧本](./module-prds/episode-script.md)。

### 9.11 内容编辑（未实现）

版本记录和编辑管理。占位规格见 [内容编辑](./module-prds/content-editing.md)。

### 9.12 Markdown 导出（未实现）

项目内容导出为 Markdown。占位规格见 [Markdown 导出](./module-prds/markdown-export.md)。

## 10. 非功能需求

### 10.1 可用性

- 第一版界面应以清晰、实用、低干扰为主。
- 用户应能明确知道当前处于哪个创作阶段。
- 每个生成动作都应有清晰入口和结果展示。
- 项目时长超限时，应明确提示是单集时长超限还是总时长超限。

### 10.2 可控性

- AI 生成内容必须允许人工编辑。
- 关键内容被覆盖前应有保护机制。
- 用户应能按模块重新生成，而不是每次从头开始。
- 人物示意图应允许单人单独重新生成，避免影响其他人物。

### 10.3 一致性

- 项目资料 / 资产、故事文本和短剧制作之间应保持单向依赖：项目资料 / 资产影响故事文本，故事文本影响短剧制作。
- 故事文本包含整体故事大纲、分集大纲和每集单集故事正文，目标是形成可读的故事 / 小说化文本。
- 短剧制作包含单集脚本、分镜、字幕和发布文案，目标是把每集单集故事正文转换成视频生产所需文本。
- 短剧制作阶段不得直接修改世界观和角色，只能沿用当前项目已保存或已确认的世界观、角色和故事文本。
- 整体故事大纲、人物设定、分集大纲、单集故事正文和剧本之间应尽量保持一致。
- 后续生成应基于用户确认过的最新内容。
- 已确认人物示意图应作为后续视觉资产生成的人物参考。

### 10.4 可扩展性

- 第一期的数据结构应为第二期分镜、第三期配音字幕、第四期视频生成预留扩展空间。
- 剧本、人物、大纲、人物图片等内容应尽量结构化保存。

### 10.5 内容安全

- 系统应避免主动生成明显违法、侵权或高风险内容。
- 对可能涉及敏感题材、抄袭风险或平台审核风险的内容，应提供提示。
- 参考故事结构抽取必须输出去具体化框架，不得复述原作具体角色、地名、专有设定、经典桥段、对白或原文表达。
- 人物示意图生成应避免生成侵犯真实人物肖像权或明显指向特定现实人物的相似形象。

## 11. 项目级实现决策

- 第一期以单用户本地项目或单用户工作台为核心，不做账号体系。
- 主数据库确定为 PostgreSQL，本地开发通过 Docker Compose 启动。
- 包含模型 API 配置能力，支持用户配置自己的文本生成模型和图片生成模型。
- 图片模型配置以多供应商可扩展为目标，支持供应商预设和自定义配置。
- 纳入创作资产库设计，支持世界观和角色卡在项目外独立管理并被项目复用。
- 世界观和角色卡加载到项目后采用快照副本模型，不采用实时共享引用模型。
- 项目工作台 v1 按“项目资料 / 资产、故事文本、短剧制作”组织内容，先支持人工维护，不要求接入 AI 生成。
- 项目资料 / 资产负责基础信息、世界观和角色；故事文本负责整体故事大纲、分集大纲和每集单集故事正文；短剧制作负责单集脚本、分镜、字幕和发布文案。
- 短剧制作阶段只能引用项目资料 / 资产和故事文本，不能提供直接修改世界观或角色的入口；如需修改，用户必须回到上游区域调整。
- 单集时长超过 2 分钟或总时长超过 240 分钟时，采用强校验：阻止保存和生成。
- 项目工作台内创作产物使用 draft、confirmed、needs_review 状态管理。
- 所有 AI 生成文本结果都必须可编辑。
- 分集正文创作工作台属于故事文本模块，输出是可读的单集故事正文；单集剧本属于短剧制作模块，输出是面向视频生产的场景、动作、对白和旁白。
- 分集正文创作工作台可以读取世界观、角色、设定、文风 / 参考资料和灵感作为只读参考；如需修改世界观或角色，用户仍需回到项目资料 / 资产。
- “文网”在第一期定义为文风 / 参考资料面板，用于沉淀写作规则、风格参考或外部参考摘要。
- 参考故事结构抽取必须使用独立的结构抽取 Skill 或规则模板，不得复用普通摘要、普通改写或普通故事大纲生成 Prompt。
- 故事大纲 AI 协助创作必须使用独立的对话式协助 Skill 或规则模板，不得复用普通故事大纲生成或参考故事结构抽取 Prompt。
- 数据应尽量结构化，避免只保存一整段不可解析文本。
- Markdown 导出作为第一期唯一必须支持的导出格式。

## 12. 端到端验收路径

### 12.1 测试原则

- 测试用户可见行为，不测试模型内部实现。
- 测试数据保存、编辑、重新生成和导出是否可靠。
- 测试核心流程能否从项目创建走到人物示意图确认、剧本生成和导出。
- 测试时长强校验是否可靠。

### 12.2 项目工作台 v1 验收路径

1. 用户创建一个新项目。
2. 用户输入短剧创意、集数和单集时长。
3. 系统校验总时长和单集时长。
4. 用户进入项目工作台。
5. 用户进入“项目资料 / 资产”，加载或维护世界观和角色卡。
6. 用户进入“故事文本”，人工维护整体故事大纲、分集大纲和单集故事正文。
7. 用户进入“短剧制作”，人工维护单集剧本、分镜和文案。
8. 用户修改上游内容后，下游显示需要检查。
9. 用户在短剧制作阶段不能直接修改世界观和角色，只能回到上游区域调整。

### 12.3 后续生成闭环验收路径

1. 用户配置文本和图片模型 API 并测试成功。
2. 用户生成选题策划 → 编辑 → 生成整体故事大纲 → 编辑。
3. 用户生成人物设定 → 生成人物示意图 → 确认。
4. 用户生成分集大纲 → 选择一集生成或润色单集故事正文 → 基于正文生成剧本 → 改写。
5. 用户导出 Markdown 文件。

### 12.4 跨模块验收标准

- 时长超限系统阻止保存。
- 模型未配置或不可用时阻止对应生成任务。
- 项目内修改不影响资产库原始内容。
- 资产库更新不自动覆盖项目内快照。
- 上游变更后下游内容显示需要检查。
- 短剧制作内容沿用项目世界观、角色和故事文本，尤其是对应集单集故事正文，不提供直接编辑世界观或角色的入口。
- Markdown 导出不包含 API Key。

## 13. 不做范围

第一期明确不做：

- AI 视频生成。
- 场景图生成。
- 分镜图生成。
- AI 自动分镜拆解。
- 配音生成。
- 字幕文件生成。
- 在线剪辑。
- 自动发布到平台。
- 团队协作。
- 用户账号和权限。
- 支付系统。
- 数据分析看板。
- 移动端专门适配。

说明：

- 第一期支持人物示意图生成，但不支持场景图、分镜图或完整视频生成。
- 项目工作台 v1 支持人工维护分镜镜头和文案，但不支持 AI 自动分镜拆解、分镜图生成、配音音频生成或字幕文件生成。

## 14. 风险与待确认问题

### 14.1 风险

- AI 生成内容可能套路化，需要通过提示词和改写能力优化。
- 长剧集一致性可能不足，需要确保后续生成引用最新整体故事大纲和人物设定。
- 人物示意图可能与文字设定不完全一致，需要支持重新生成和人工确认。
- 用户可能希望第一期就生成视频，需要通过产品定位控制预期。
- 如果数据结构设计过于松散，第二期分镜会比较难接。
- 图片生成能力会引入额外成本和生成耗时，需要在后续技术方案中控制调用频率和缓存。

### 14.2 待确认问题

- 第一版是否只做本地应用，还是直接做 Web 应用。
- 第一版是否提供常见模型供应商的配置模板。
- 第一版 API Key 是否需要系统级加密存储。
- 第一版目标平台是否优先围绕抖音短剧节奏设计。
- 是否需要在第一期加入内容合规提示。

## 15. 后续阶段衔接

第一期输出应为第二期分镜与制作资料工作台、第四期 AI 视觉资产与视频生成接入提供结构化输入。

第二期将基于第一期的单集剧本继续拆解：

```text
单集剧本 -> 场景 -> 镜头 -> 分镜描述 -> AI 图像/视频提示词 -> 制作清单
```

第四期将基于第一期确认的人物示意图继续扩展：

```text
人物设定 -> 人物示意图 -> 人物一致性参考 -> 镜头级视觉素材生成 -> 视频生成
```

因此，第一期在保存剧本时，应尽量保留场景、角色、动作、对白等结构；在保存人物时，应保留文字设定、视觉描述、图片提示词和已确认示意图引用，避免后续只能从纯文本重新解析。
