# 模块 PRD：项目工作台

## 1. 功能定位

项目工作台 v1 用于把项目从"基础资料"升级为可推进创作流程的工作台。该版本先不要求 AI 自动生成，而是提供人工编辑、保存、回显和状态检查能力。

## 2. 阶段导航

项目工作台 v1 分区：

- 基础信息
- 世界观与角色
- 整体故事大纲
- 分集大纲
- 单集内容
- 单集剧本
- 分镜与文案

后续生成能力扩展分区：

- 选题策划
- 人物设定
- 人物示意图
- 导出

## 3. 内容状态机

### 3.1 状态定义

表示项目内创作产物状态（`ProjectArtifactStatus`）。

枚举值：

- `draft`：草稿，内容尚未确认。
- `confirmed`：已确认，可作为后续内容基准。
- `needs_review`：上游内容发生变化，需要人工检查。

规则：

- 上游内容变更时，下游已存在创作产物进入 `needs_review`。
- 用户人工检查并保存后，可以重新设为 `draft` 或 `confirmed`。

### 3.2 上游变更传播规则

- 修改项目设定后，整体故事大纲、分集大纲、单集内容、剧本、分镜和文案标记为 `needs_review`。
- 保存项目世界观或项目角色快照的微调内容后，下游创作内容标记为 `needs_review`。
- 移除项目世界观或角色快照后，下游创作内容标记为 `needs_review`。
- 保存整体故事大纲后，分集大纲、单集内容、剧本、分镜和文案标记为 `needs_review`。
- 保存某集分集大纲后，同集单集内容、剧本、分镜和文案标记为 `needs_review`。
- 保存某集单集内容后，同集剧本、分镜和文案标记为 `needs_review`。
- 保存某集剧本后，同集分镜和文案标记为 `needs_review`。

## 4. 工作台能力清单

### 4.1 基础能力（§9.3A）

- 用户可以读取项目详情并编辑项目基础信息。
- 用户可以查看已加载的世界观和角色快照。
- 用户可以在"世界观与角色"阶段内直接打开资产选择面板，从世界观库和角色卡库中选择并加载到当前项目，无需跳转到资产库页面。
- 用户可以在项目内微调已加载的世界观和角色快照，微调内容只影响当前项目，不回写世界观库或角色卡库原始内容。
- 用户可以从项目中移除世界观或角色快照，且不影响资产库原始内容。
- 用户可以人工维护整体故事大纲。
- 用户可以按项目集数维护分集大纲。
- 用户可以选择某一集维护详细剧情内容和关键剧情节拍。
- 用户可以选择某一集维护剧本中的场景说明、对白、动作说明和旁白。
- 用户可以选择某一集维护分镜镜头，包括镜头序号、场景、画面提示词、镜头/机位、镜头时长、对白或旁白。
- 用户可以选择某一集维护字幕、平台标题、平台简介和发布文案。

### 4.2 世界观与角色加载规则

项目工作台中的"世界观与角色"阶段负责把资产库内容快速引用到当前项目中。这里的"引用"不是实时共享引用，而是用已有资产初始化项目内可编辑快照。

#### 4.2.1 项目世界观

项目世界观用于约束当前项目的时代背景、世界规则、组织、地点、社会结构、禁忌限制和整体风格。

规则：

- 每个项目最多只能加载一个世界观快照。
- 只有 `active` 世界观可以加载到项目。
- 当项目尚未加载世界观时，用户可以从世界观库选择一个世界观并加载。
- 当项目已有世界观时，前端应阻止继续加载第二个世界观；如需更换，应先移除当前项目世界观，或后续提供明确的替换操作。
- 加载世界观时，系统复制世界观基础信息和启用条目，生成 `ProjectWorldSnapshot`。
- 项目世界观加载后可以在项目内微调，例如调整项目专用的世界规则补充、地点说明、禁忌限制、风格约束或条目内容。
- 项目内微调只修改 `ProjectWorldSnapshot`，不修改 `WorldBook` 或 `WorldEntry` 原始内容。
- 后续生成任务读取项目世界观快照，不直接读取世界观库原文。

验收标准：

- 项目没有世界观时，可以加载一个 active 世界观。
- 项目已有世界观时，不能再加载第二个世界观。
- 用户可以保存项目世界观微调内容。
- 保存项目世界观微调内容后，资产库原始世界观不变。

#### 4.2.2 项目角色

项目角色用于在当前项目中快速复用角色卡库的人物基础、人设原型、核心欲望、口吻和视觉素材，并允许为当前项目做局部调整。

规则：

- 每个项目可以加载多个角色快照。
- 只有 `active` 角色卡可以加载到项目。
- 同一角色卡不能在同一项目中重复加载。
- 已加载的角色在资产选择面板中应标记为"已加载"，不可再次选择。
- 加载角色卡时，系统复制角色基础设定、性别、人设原型、核心欲望、口吻、视觉描述、参考图和来源信息，生成 `ProjectCharacterSnapshot`。
- 项目角色加载后可以在项目内微调，例如调整当前项目中的人物目标、人物关系、冲突点、反转秘密、情感弧线、剧情功能、口吻补充或视觉描述。
- 项目内微调只修改 `ProjectCharacterSnapshot`，不修改 `CharacterCard` 原始内容。
- 后续生成任务读取项目角色快照，不直接读取角色卡库原文。

验收标准：

- 项目可以加载多个 active 角色卡。
- 同一角色卡在同一项目中不可重复加载。
- 用户可以保存项目角色微调内容。
- 保存项目角色微调内容后，角色卡库原始角色不变。

### 4.3 生成结果编辑区（§11.5）

- 展示 AI 输出。
- 支持人工编辑。
- 支持重新生成和局部改写。

核心操作：

- 保存
- 重新生成
- 局部改写
- 使用当前版本
- 查看历史版本

### 4.4 人物示意图确认区（§11.6）

- 展示人物视觉描述、图片提示词和生成结果。
- 支持重新生成单个人物示意图。
- 支持确认当前图片为角色参考形象。

核心操作：

- 生成示意图
- 重新生成
- 确认为参考形象
- 查看图片提示词

## 7. 实现决策

- 项目工作台 v1 先支持人工维护整体故事大纲、分集大纲、单集内容、剧本、分镜镜头和发布文案，不要求接入 AI 生成。
- 项目工作台 v1 支持在工作台内直接选择并加载世界观和角色卡，用户无需跳转到资产库页面即可完成资产加载。
- 整体故事大纲是独立模块，不合并进选题策划。
- 整体故事大纲位于人物设定之前，后续人物、分集和剧本生成都应引用它。
- 世界观和角色卡加载到项目后采用快照副本模型，不采用实时共享引用模型。
- 项目世界观每个项目最多一个；项目角色可以多个，但同一角色卡不能在同一项目中重复加载。
- 项目世界观和项目角色快照可以在当前项目内微调，微调只更新项目快照，不回写资产库原始内容。
- 项目内快照优先于资产库原文参与生成；资产库原文更新不自动覆盖项目快照。
- 单集时长超过 2 分钟或总时长超过 240 分钟时，采用强校验：阻止保存和生成。
- 项目工作台内创作产物使用 `draft`、`confirmed`、`needs_review` 状态管理；上游内容变更时标记下游内容需要检查，不自动覆盖用户已编辑内容。
- 人物设定后支持生成主要人物示意图。
- 人物示意图优先服务角色确认和后续视频一致性参考，不要求做到专业角色一致性训练。
- 所有 AI 生成文本结果都必须可编辑。
- 后续生成应优先使用用户确认后的最新内容。
- 数据应尽量结构化，避免只保存一整段不可解析文本。
- Markdown 导出作为第一期唯一必须支持的导出格式。
- 版本记录先做轻量历史，不做复杂协同编辑和差异对比。
- 分镜镜头和发布文案字段进入项目工作台 v1，用于人工维护和后续生成衔接；AI 自动分镜、配音、字幕文件和视频生成仍不进入 v1。

## 8. 验收标准

### 8.1 工作台 v1 验收标准

- 项目列表可以进入 `/projects/{project_id}`。
- 创建项目成功后进入项目工作台。
- 工作台阶段导航可以切换。
- 项目基础信息保存后刷新不丢失。
- 用户可在工作台"世界观与角色"阶段内直接选择并加载世界观和角色卡，加载后快照列表自动刷新。
- 每个项目最多只能加载一个世界观，已有世界观时不能继续加载第二个世界观。
- 项目可以加载多个角色，但同一角色卡不能重复加载到同一项目。
- 用户可以在项目内微调已加载的世界观和角色快照，保存后刷新不丢失。
- 项目内微调不修改世界观库或角色卡库原始内容。
- 已加载的资产在选择面板中标记为"已加载"且不可重复选择。
- 整体故事大纲、分集大纲、单集内容、剧本、分镜和文案均可保存并回显。
- 上游内容变更后，已存在的下游内容显示为"需要检查"。
- 删除项目内快照不删除资产库原始世界观或角色卡。

### 8.2 核心验收路径

项目工作台 v1 验收路径：

1. 用户创建一个新项目。
2. 用户输入短剧创意、集数和单集时长。
3. 系统校验总时长和单集时长。
4. 用户进入项目工作台。
5. 用户查看并编辑项目基础信息。
6. 用户在工作台"世界观与角色"阶段内直接选择并加载世界观和角色卡到项目中。
7. 用户查看并移除项目内世界观或角色快照。
8. 用户人工维护整体故事大纲并保存。
9. 用户人工维护完整分集大纲并保存。
10. 用户选择第 1 集维护单集详细内容。
11. 用户维护第 1 集剧本。
12. 用户维护第 1 集分镜镜头。
13. 用户维护第 1 集字幕、平台标题、平台简介和发布文案。
14. 用户修改项目设定或移除某个快照后，下游内容显示需要检查。

后续生成闭环验收路径：

1. 用户配置文本生成模型 API 并测试成功。
2. 用户配置图片生成模型 API 并测试成功。
3. 用户编辑项目内世界观和角色卡副本。
4. 用户生成选题策划。
5. 用户编辑并保存选题策划。
6. 用户生成整体故事大纲与剧情脉络。
7. 用户编辑并保存整体故事大纲。
8. 用户生成人物设定。
9. 用户编辑某个人物。
10. 用户为主要人物生成示意图。
11. 用户确认某个人物示意图。
12. 用户生成完整分集大纲。
13. 用户选择第 1 集生成剧本。
14. 用户对剧本执行一次改写。
15. 用户导出 Markdown 文件。
