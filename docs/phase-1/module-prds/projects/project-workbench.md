# 模块 PRD：项目工作台

## 1. 功能定位

项目工作台 v1 用于把项目从"基础资料"升级为可推进创作流程的工作台。该版本先不要求 AI 自动生成，而是提供人工编辑、保存、回显和状态检查能力。

工作台必须按三类工作区域组织：

- 项目资料 / 资产：维护基础信息、世界观和角色，作为整个项目的公共上下文。
- 故事文本：负责把项目写成完整故事，包含整体故事大纲、分集大纲和每集单集故事正文，目标是形成可读的故事 / 小说化文本。
- 短剧制作：负责把每集单集故事正文转成视频生产所需文本，包括单集脚本、分镜、字幕和平台文案。

短剧制作阶段只能沿用项目资料 / 资产和故事文本中的世界观、角色、整体故事大纲、分集大纲和每集单集故事正文，不允许直接修改世界观或角色，防止后续制作文本与前期故事设定冲突。

## 2. 工作台入口与分区

项目工作台 v1 首屏应先呈现三个工作入口，而不是直接进入线性阶段列表：

### 2.1 项目资料 / 资产

包含：

- 基础信息。
- 世界观。
- 角色。

三个区域在项目资料 / 资产模块顶部作为同级入口展示。世界观入口展示已加载数量与单项目上限（`0/1` 或 `1/1`），角色入口展示当前已加载角色数量，不再设置“世界观与角色”二级入口。

职责：

- 维护项目基础约束，例如题材、平台、集数、单集时长和备注。
- 从世界观库和角色卡库加载资产，生成项目内快照。
- 在项目内微调世界观和角色快照。
- 为故事文本和短剧制作提供统一上下文。

### 2.2 故事文本

包含：

- 整体故事大纲。
- 分集大纲。
- 单集故事正文创作工作台。

职责：

- 把项目写成完整故事。
- 先确定整体结构，再确定分集结构，最后维护每集单集故事正文。
- 输出可读的故事 / 小说化文本。
- 作为短剧制作的主要输入来源。

单集故事正文创作工作台采用三栏信息架构：

- 左侧：分集列表，展示集数、标题、状态、完成提示和当前集高亮。
- 中间：正文创作区，展示上游大纲参考、正文元信息、正文编辑区、字数、状态、保存和 AI 写作操作。
- 右侧：设定 / 角色 / 文风 / 灵感面板，展示世界观、角色、设定约束、文风参考、灵感和质检入口。

上游大纲参考只读展示分集大纲中的标题、本集梗概、开场钩子、本集冲突、关键反转和结尾悬念；这些写作计划字段仍在分集大纲中编辑。正文元信息用于维护正文摘要。前文参考只读展示上一集正文摘要，不在正文页手动编辑。正文节拍不作为一期正文页独立展示字段，如后续 AI 需要节拍输入，应由分集大纲中的开场钩子、本集冲突、关键反转和结尾悬念组合生成。

右侧参考面板可以帮助正文创作和一致性质检，但不改变项目资料 / 资产的上游规则。世界观和角色如需修改，仍应回到项目资料 / 资产入口。

### 2.3 短剧制作

包含：

- 单集剧本。
- 分镜与文案。

职责：

- 针对每一集，把故事文本转换成视频生产所需文字内容。
- 维护单集脚本、分镜镜头、字幕、平台标题、平台简介和发布文案。
- 沿用项目资料 / 资产和故事文本，不直接编辑世界观或角色。

## 3. 内容状态机

### 3.1 状态定义

表示项目内创作产物状态（`ProjectArtifactStatus`）。

枚举值：

- `draft`：草稿，内容尚未确认。
- `confirmed`：已确认，可作为后续内容基准。
- `needs_review`：上游内容发生变化，需要人工检查。

规则：

- 上游内容变更时，下游已存在创作产物进入 `needs_review`。
- 用户人工检查并保存后，可以重新设为 `draft` 或 `confirmed`。

### 3.2 上游变更传播规则

`needs_review` 表示内容仍然保留，但因为上游内容变化，可能不再一致，需要用户重新检查、编辑或重新生成。

传播规则：

- 修改项目基础信息后，故事文本和短剧制作下的已有内容标记为 `needs_review`。
- 保存项目世界观或项目角色快照的微调内容后，故事文本和短剧制作下的已有内容标记为 `needs_review`。
- 移除项目世界观或角色快照后，故事文本和短剧制作下的已有内容标记为 `needs_review`。
- 保存整体故事大纲后，分集大纲、单集故事正文、剧本、分镜和文案标记为 `needs_review`。
- 保存某集分集大纲后，同集单集故事正文、剧本、分镜和文案标记为 `needs_review`。
- 保存某集单集故事正文后，同集剧本、分镜和文案标记为 `needs_review`。
- 保存某集剧本后，同集分镜和文案标记为 `needs_review`。

状态传播只做提示，不自动删除、覆盖或重新生成下游内容。用户检查后可以手动保存并将内容重新设为 `draft` 或 `confirmed`。

## 4. 工作台能力清单

### 4.1 基础能力（§9.3A）

- 用户可以读取项目详情并编辑项目基础信息。
- 用户可以查看已加载的世界观和角色快照。
- 用户可以在"项目资料 / 资产"区域内直接打开资产选择面板，从世界观库和角色卡库中选择并加载到当前项目，无需跳转到资产库页面。
- 用户可以在项目内微调已加载的世界观和角色快照，微调内容只影响当前项目，不回写世界观库或角色卡库原始内容。
- 用户可以从项目中移除世界观或角色快照，且不影响资产库原始内容。
- 用户可以进入“故事文本”维护整体故事大纲。
- 用户可以在“故事文本”按项目集数维护分集大纲。
- 用户可以在“故事文本”选择某一集进入单集故事正文创作工作台，只读查看上游大纲参考和上一集正文摘要，并维护正文、正文摘要和状态。
- 用户可以在单集故事正文创作工作台中执行 AI 正文创作、续写、润色、撤销润色、摘要和一致性质检。
- 用户可以在单集故事正文创作工作台右侧查看世界观、角色、设定、文风 / 参考资料和灵感参考面板。
- 用户可以进入“短剧制作”选择某一集维护剧本中的场景说明、对白、动作说明和旁白。
- 用户可以在“短剧制作”选择某一集维护分镜镜头，包括镜头序号、场景、画面提示词、镜头/机位、镜头时长、对白或旁白。
- 用户可以在“短剧制作”选择某一集维护字幕、平台标题、平台简介和发布文案。

### 4.2 世界观与角色加载规则

项目工作台中的"项目资料 / 资产"区域负责把资产库内容快速引用到当前项目中。这里的"引用"不是实时共享引用，而是用已有资产初始化项目内可编辑快照。

#### 4.2.1 项目世界观

项目世界观用于约束当前项目的时代背景、世界规则、组织、地点、社会结构、禁忌限制和整体风格。

规则：

- 每个项目最多只能加载一个世界观快照。
- 只有 `active` 世界观可以加载到项目。
- 当项目尚未加载世界观时，用户可以从世界观库选择一个世界观并加载。
- 当项目已有世界观时，前端应阻止继续加载第二个世界观；如需更换，应先移除当前项目世界观，或后续提供明确的替换操作。
- 加载世界观时，系统复制世界观基础信息和启用条目，生成 `ProjectWorldSnapshot`。
- 项目世界观加载后可以在项目内微调，例如调整项目专用的世界规则补充、地点说明、禁忌限制、风格约束或条目内容。
- 项目内微调只修改 `ProjectWorldSnapshot`，不修改 `WorldBook` 或 `WorldEntry` 原始内容。
- 后续生成任务读取项目世界观快照，不直接读取世界观库原文。

验收标准：

- 项目没有世界观时，可以加载一个 active 世界观。
- 项目已有世界观时，不能再加载第二个世界观。
- 用户可以保存项目世界观微调内容。
- 保存项目世界观微调内容后，资产库原始世界观不变。

#### 4.2.2 项目角色

项目角色用于在当前项目中快速复用角色卡库的人物基础、人设原型、核心欲望、口吻和视觉素材，并允许为当前项目做局部调整。

规则：

- 每个项目可以加载多个角色快照。
- 只有 `active` 角色卡可以加载到项目。
- 同一角色卡不能在同一项目中重复加载。
- 已加载的角色在资产选择面板中应标记为"已加载"，不可再次选择。
- 加载角色卡时，系统复制角色基础设定、性别、人设原型、核心欲望、口吻、视觉描述、参考图和来源信息，生成 `ProjectCharacterSnapshot`。
- 项目角色加载后可以在项目内微调，例如调整当前项目中的人物目标、人物关系、冲突点、反转秘密、情感弧线、剧情功能、口吻补充或视觉描述。
- 项目内微调只修改 `ProjectCharacterSnapshot`，不修改 `CharacterCard` 原始内容。
- 后续生成任务读取项目角色快照，不直接读取角色卡库原文。

验收标准：

- 项目可以加载多个 active 角色卡。
- 同一角色卡在同一项目中不可重复加载。
- 用户可以保存项目角色微调内容。
- 保存项目角色微调内容后，角色卡库原始角色不变。

### 4.3 短剧制作上游锁定规则

短剧制作阶段负责把每集单集故事正文转换为视频生产所需文本，不负责重新定义项目世界观、角色或故事走向。

规则：

- 短剧制作阶段不提供项目世界观和项目角色的直接编辑入口。
- 短剧制作阶段生成或编辑单集剧本、分镜、字幕和发布文案时，必须沿用项目资料 / 资产中的世界观和角色快照。
- 短剧制作阶段必须优先引用故事文本中的整体故事大纲、对应分集大纲和对应单集故事正文。
- 如果用户在短剧制作阶段发现世界观、角色或故事内容需要调整，应回到项目资料 / 资产或故事文本中修改。
- 用户修改上游内容后，短剧制作下的已有脚本、分镜和文案进入 `needs_review`。
- 短剧制作阶段可以补充镜头表达、对白组织、字幕和发布文案，但不能新增与上游世界观、角色或单集故事正文冲突的设定。

验收标准：

- 用户在短剧制作区域无法直接编辑世界观和角色快照。
- 用户修改世界观、角色、整体故事大纲、分集大纲或单集故事正文后，相关短剧制作内容显示为"需要检查"。
- 单集剧本、分镜和文案应能明确追溯到对应单集故事正文。

### 4.4 生成结果编辑区（§11.5）

- 展示 AI 输出。
- 支持人工编辑。
- 支持重新生成和局部改写。

核心操作：

- 保存
- 重新生成
- 局部改写
- 使用当前版本
- 查看历史版本

### 4.5 人物示意图确认区（§11.6）

- 展示人物视觉描述、图片提示词和生成结果。
- 支持重新生成单个人物示意图。
- 支持确认当前图片为角色参考形象。

核心操作：

- 生成示意图
- 重新生成
- 确认为参考形象
- 查看图片提示词

## 7. 实现决策

- 项目工作台 v1 先支持人工维护项目资料 / 资产、故事文本和短剧制作文本；分集正文创作工作台的 AI 能力作为第一期后续子阶段接入。
- 项目资料 / 资产包含基础信息、世界观和角色。
- 项目资料 / 资产模块顶部使用基础信息、世界观、角色三个同级入口；世界观显示 `0/1` 或 `1/1`，角色显示已加载数量。
- 故事文本包含整体故事大纲、分集大纲和单集故事正文。
- 短剧制作包含单集剧本、分镜镜头、字幕、传播点和发布文案。
- 项目工作台 v1 支持在工作台内直接选择并加载世界观和角色卡，用户无需跳转到资产库页面即可完成资产加载。
- 整体故事大纲是独立模块，不合并进选题策划。
- 整体故事大纲位于人物设定之前，后续人物、分集和剧本生成都应引用它。
- 世界观和角色卡加载到项目后采用快照副本模型，不采用实时共享引用模型。
- 项目世界观每个项目最多一个；项目角色可以多个，但同一角色卡不能在同一项目中重复加载。
- 项目世界观和项目角色快照可以在当前项目内微调，微调只更新项目快照，不回写资产库原始内容。
- 项目内快照优先于资产库原文参与生成；资产库原文更新不自动覆盖项目快照。
- 单集时长超过 2 分钟或总时长超过 240 分钟时，采用强校验：阻止保存和生成。
- 项目工作台内创作产物使用 `draft`、`confirmed`、`needs_review` 状态管理；上游内容变更时标记下游内容需要检查，不自动覆盖用户已编辑内容。
- 短剧制作阶段只能沿用项目资料 / 资产和故事文本，不能直接修改世界观或角色；如需修改，用户必须回到上游区域调整。
- 短剧制作的主要输入是对应集的单集故事正文，同时引用整体故事大纲、分集大纲、世界观和角色快照。
- 单集故事正文创作工作台归属于故事文本，采用三栏布局：分集列表、正文编辑区、上下文参考面板。
- 单集故事正文创作工作台可提供 AI 创作、续写、润色、撤销润色、摘要、一致性质检、角色参考、设定参考、文风 / 参考资料和灵感面板。钩子提取归入短剧制作。
- 右侧参考面板可以展示世界观和角色，但不作为项目资料 / 资产的直接编辑入口。
- 人物设定后支持生成主要人物示意图。
- 人物示意图优先服务角色确认和后续视频一致性参考，不要求做到专业角色一致性训练。
- 所有 AI 生成文本结果都必须可编辑。
- 后续生成应优先使用用户确认后的最新内容。
- 数据应尽量结构化，避免只保存一整段不可解析文本。
- Markdown 导出作为第一期唯一必须支持的导出格式。
- 版本记录先做轻量历史，不做复杂协同编辑和差异对比。
- 分镜镜头和发布文案字段进入项目工作台 v1，用于人工维护和后续生成衔接；AI 自动分镜、配音、字幕文件和视频生成仍不进入 v1。

## 8. 验收标准

### 8.1 工作台 v1 验收标准

- 项目列表可以进入 `/projects/{project_id}`。
- 创建项目成功后进入项目工作台。
- 工作台首屏或主导航应清晰呈现项目资料 / 资产、故事文本、短剧制作三个入口。
- 项目资料 / 资产模块顶部应清晰呈现基础信息、世界观、角色三个同级入口，不再嵌套“世界观与角色”二级入口。
- 项目基础信息保存后刷新不丢失。
- 用户可在工作台"项目资料 / 资产"区域内直接选择并加载世界观和角色卡，加载后快照列表自动刷新。
- 每个项目最多只能加载一个世界观，已有世界观时不能继续加载第二个世界观。
- 项目可以加载多个角色，但同一角色卡不能重复加载到同一项目。
- 用户可以在项目内微调已加载的世界观和角色快照，保存后刷新不丢失。
- 项目内微调不修改世界观库或角色卡库原始内容。
- 已加载的资产在选择面板中标记为"已加载"且不可重复选择。
- 故事文本区域中的整体故事大纲、分集大纲和单集故事正文均可保存并回显。
- 单集故事正文创作工作台应支持从分集列表选择某一集，只读查看上游大纲参考并编辑正文。
- 单集故事正文创作工作台应展示正文摘要、只读前文参考、右侧世界观 / 角色 / 设定 / 文风 / 灵感参考和质检结果入口。
- 短剧制作区域中的剧本、分镜和文案均可保存并回显。
- 短剧制作区域不提供世界观和角色的直接编辑入口。
- 上游内容变更后，已存在的下游内容显示为"需要检查"。
- 删除项目内快照不删除资产库原始世界观或角色卡。

### 8.2 核心验收路径

项目工作台 v1 验收路径：

1. 用户创建一个新项目。
2. 用户输入短剧创意、集数和单集时长。
3. 系统校验总时长和单集时长。
4. 用户进入项目工作台。
5. 用户查看并编辑项目基础信息。
6. 用户进入"项目资料 / 资产"，直接选择并加载世界观和角色卡到项目中。
7. 用户查看并移除项目内世界观或角色快照。
8. 用户进入"故事文本"，人工维护整体故事大纲并保存。
9. 用户人工维护完整分集大纲并保存。
10. 用户选择第 1 集进入单集故事正文创作工作台，维护正文、摘要和钩子。
11. 用户进入"短剧制作"，基于第 1 集单集故事正文维护剧本。
12. 用户维护第 1 集分镜镜头。
13. 用户维护第 1 集字幕、平台标题、平台简介和发布文案。
14. 用户在短剧制作区域确认无法直接编辑世界观和角色。
15. 用户修改项目设定、世界观、角色或故事文本后，下游内容显示需要检查。

后续生成闭环验收路径：

1. 用户配置文本生成模型 API 并测试成功。
2. 用户配置图片生成模型 API 并测试成功。
3. 用户编辑项目内世界观和角色卡副本。
4. 用户生成选题策划。
5. 用户编辑并保存选题策划。
6. 用户生成整体故事大纲与剧情脉络。
7. 用户编辑并保存整体故事大纲。
8. 用户生成人物设定。
9. 用户编辑某个人物。
10. 用户为主要人物生成示意图。
11. 用户确认某个人物示意图。
12. 用户生成完整分集大纲。
13. 用户选择第 1 集生成或润色单集故事正文。
14. 用户基于第 1 集单集故事正文生成剧本。
15. 用户对剧本执行一次改写。
16. 用户导出 Markdown 文件。
