# 模块 PRD：角色卡库

## 1. 功能定位

角色卡库用于独立管理可复用人物设定。

它解决的问题是：用户可能会在多个短剧项目中复用某类人物资产、系列角色或已经确认过视觉方向的人物，不希望每次都重新设计人物身份、人设原型、核心欲望、口吻和外观。

角色卡库只管理资产库中的原始角色卡。角色卡被加载到项目后，会生成项目内快照副本；项目内快照的编辑和引用规则见创作资产库相关文档。

角色卡库不负责塑造具体项目剧情。人物关系、冲突点、反转秘密、情感弧线和剧情功能应在项目角色快照、项目人物设定、故事大纲或世界观中完成。

## 2. 背景

AI 短剧制作工具需要帮助创作者持续产出短剧项目。随着项目数量增加，用户会反复使用相似人物类型、系列角色或已经确认过视觉方向的人物。

如果每个项目都重新设计角色，用户会遇到以下问题：

- 角色设定重复输入，创作效率低。
- 同一系列角色在不同项目中容易出现身份、人设原型、核心欲望、口吻和视觉描述不一致。
- 已经确认过的人物视觉方向无法沉淀为可复用资产。
- 项目内临时改写角色时，容易误改原始角色设定，影响其他项目。

角色卡库用于把可复用人物设定从具体项目中抽离出来，形成独立资产。角色卡被加载到项目后生成项目内快照副本，项目内修改不会影响角色卡库原始内容。

## 3. 用户场景

目标用户：

- 个人短剧创作者。
- 希望批量创作同题材、同系列或相似人设短剧的创作者。
- 希望通过 AI 保持角色设定和视觉方向一致的创作者。

核心场景：

- 用户沉淀一个常用女主角色，例如"隐忍复仇型豪门继承人"，后续可加载到多个都市逆袭项目。
- 用户为一个系列短剧维护固定系列人物，后续不同项目可以复用并局部调整。
- 用户已经生成并确认某个角色示意图，希望角色卡中保留视觉描述和参考图，后续项目继续使用。
- 用户在某个项目里调整具体剧情目标、人物关系或冲突，但不希望影响角色卡库中的原始人物资产。

## 4. 功能范围

第一期包括：

- 角色卡列表。
- 角色卡新建。
- 角色卡详情查看。
- 角色卡基础信息编辑。
- 角色人设原型、核心欲望和稳定性格维护。
- 角色口吻与对白风格维护。
- 角色视觉描述、形象关键词和参考图引用维护。
- 角色卡状态管理。
- 角色卡被项目加载前的预览。
- 角色卡加载到项目后生成项目内快照。
- 项目内角色快照编辑不影响角色卡库原始内容。

第一期角色卡库不再承载具体项目剧情。人物关系、冲突点、反转秘密、情感弧线和剧情功能应在项目角色快照、项目人物设定、故事大纲或世界观中塑造。

第一期不包括：

- 专业角色一致性训练。
- 复杂人物关系图。
- 多角色对话模拟。
- 自动同步角色卡新版本到已加载项目。
- 角色卡版本差异对比。
- 多人共享角色资产。

## 5. 核心流程

### 5.1 创建角色卡

```text
进入角色卡库
 -> 点击新建角色卡
 -> 填写角色基础身份
 -> 选择角色性别
 -> 选择人物原型
 -> 填写核心欲望 / 人物执念
 -> 填写说话方式和对白风格
 -> 填写视觉描述和形象关键词
 -> 在人物三视图区点击生成提示词
 -> 系统按当前字段拼接三视图生成提示词
 -> 用户手动调整提示词
 -> 可选上传参考图
 -> 保存角色卡
```

### 5.2 加载角色卡到项目

```text
进入项目创建页或项目工作台
 -> 选择角色卡
 -> 预览角色卡内容
 -> 确认加载
 -> 系统生成项目内角色快照
 -> 后续生成任务读取项目内快照
```

### 5.3 项目内调整角色

```text
进入项目工作台
 -> 打开已加载角色
 -> 修改当前项目需要的剧情目标、关系、冲突、口吻或视觉描述
 -> 保存项目内快照
 -> 原始角色卡保持不变
```

## 6. 功能需求

### 6.1 角色卡列表

用户可以查看已创建的角色卡。

列表展示：

- 角色名。
- 性别。
- 人物原型。
- 身份摘要。
- 核心欲望 / 人物执念。
- 视觉关键词。
- 是否有关联参考图。
- 状态。
- 版本。
- 更新时间。

交互要求：

- 支持新建角色卡。
- 支持进入角色卡详情。
- 支持按角色名搜索。
- 支持按性别、人物原型和状态筛选。
- 支持归档角色卡。

空状态引导：

- 当没有角色卡时，展示创建入口。
- 空状态文案应引导用户沉淀可复用角色，而不是要求一次性完成所有设定。

验收标准：

- 用户可以看到已有角色卡。
- 用户可以通过搜索或筛选快速找到目标角色。
- 没有角色卡时，页面应展示空状态和新建入口。

### 6.2 角色卡详情与编辑

用户可以维护角色的可复用人物资产设定。

页面区域：

- 基础身份区。
- 人物资产设定区。
- 口吻与对白风格区。
- 视觉设定区。
- 使用记录区。
- 操作区。

内容区域：

- 基础身份：角色名、性别、人物原型、身份摘要。
- 人物资产：背景、性格、核心欲望 / 人物执念。
- 口吻风格：说话方式、常用表达。
- 视觉设定：视觉描述、形象关键词、参考图。

不在角色卡中填写的内容：

- 具体项目剧情目标。
- 具体人物关系。
- 冲突点和反转秘密。
- 情感弧线。
- 剧情功能或集数安排。

基础身份字段规则：

- 性别字段使用 `gender` 保存。
- 性别为必填枚举，只支持男、女两个选项。
- 性别用于后续故事大纲、人物设定、人物示意图和剧本生成中的角色上下文约束。
- 人物原型继续使用 `role_type` 字段保存，但文案不再表达主角、反派、配角等项目剧情职能。
- 核心欲望 / 人物执念继续使用 `goal` 字段保存，作为兼容字段，不表示某个项目的主线目标。

使用记录区：

- 展示角色卡被加载到哪些项目中。
- 展示各项目的加载时间和来源版本。

交互要求：

- 用户可以保存角色卡。
- 用户可以继续编辑已保存角色卡。
- 用户可以归档角色卡。
- 用户可以加载角色卡到项目。

验收标准：

- 用户可以保存完整角色卡。
- 性别为必填字段，只允许选择男或女。
- 必填字段缺失时，系统应阻止保存并给出明确提示。
- 修改核心设定、视觉描述或参考图后，角色卡版本应更新。

### 6.3 视觉设定与参考图

角色卡应支持保存用于人物示意图生成和后续视频一致性参考的视觉信息。

字段建议：

- 年龄感。
- 气质。
- 发型。
- 服装。
- 脸部特征。
- 身形特征。
- 色彩倾向。
- 风格关键词。
- 参考图上传与图片引用。
- 三视图生成提示词。

视觉描述应避免直接模仿特定现实人物，避免侵犯肖像权或造成误导。

三视图生成提示词规则：

- 新建角色卡页的人物三视图区应提供"生成提示词"按钮。
- 用户点击"生成提示词"后，系统根据当前已填写字段自动拼接一段可编辑的三视图提示词。
- 自动生成的提示词应写入三视图提示词输入区，用户可以继续手动调整、增删或重写。
- 自动拼接只读取当前表单内容，不自动保存角色卡，不调用图片生成 API。
- 再次点击"生成提示词"时，如果用户已手动修改过提示词，系统应先提示确认，避免覆盖用户修改。
- 自动拼接顺序为：固定三视图规范、角色名、性别、身份摘要、视觉描述、形象关键词、人物原型、性格、核心欲望 / 人物执念、用户已填写的三视图补充内容、参考图说明。
- 固定三视图规范必须包含同一角色、正面、侧面、背面、全身、统一服装、干净背景、适合作为短剧人物视觉参考、不模仿特定现实人物。
- 视觉描述和形象关键词优先级高于剧情性字段，避免提示词被非视觉信息稀释。

验收标准：

- 用户可以保存视觉描述和形象关键词。
- 用户可以上传参考图并保存图片引用。
- 用户可以在新建角色卡页一键生成三视图提示词，并在生成三视图前手动修改。
- 视觉描述应避免直接模仿特定现实人物。

### 6.4 状态管理

角色卡状态包括：

- draft：草稿。
- active：可加载。
- archived：已归档。

规则：

- 只有 `active` 角色卡可以被加载到项目。
- `archived` 角色卡不再作为新项目可选项。
- 已归档角色卡不应从历史项目来源记录中删除。
- 第一版使用归档代替硬删除。

验收标准：

- 用户可以将角色卡从草稿改为可加载。
- 用户可以归档角色卡。
- 已归档角色卡不出现在新项目加载候选列表中。

### 6.5 项目加载与快照

用户可以把角色卡加载到项目中。

加载动作是对已有角色卡的快速引用和初始化，不是实时绑定角色卡库原文。每个项目可以加载多个角色卡，但同一角色卡不能在同一项目中重复作为新角色加载。

加载后生成项目内角色快照，快照包含：

- 角色基础设定。
- 人物原型、核心欲望、口吻。
- 视觉描述和参考图引用。
- 来源角色卡 ID。
- 来源角色卡版本。
- 加载时间。

项目内角色快照可以在角色卡基础上补充当前项目的剧情目标、人物关系、冲突点、反转秘密、情感弧线和剧情功能，这些修改不回写原始角色卡。

规则：

- 项目生成任务读取项目内角色快照。
- 项目内修改角色快照，不影响角色卡库原始内容。
- 角色卡库原始内容更新，不自动覆盖项目内快照。
- 同一角色卡可以加载到多个项目。
- 同一角色卡不能在同一项目中重复作为新角色加载；如需更新当前项目中的该角色，应明确替换已有项目角色快照。

验收标准：

- 角色卡加载到项目后，项目内存在独立快照。
- 同一项目内不能重复加载同一角色卡。
- 修改项目内快照不会修改原始角色卡。
- 修改原始角色卡不会自动覆盖已加载项目。

### 6.6 加载冲突处理

当项目中已有角色设定，再加载角色卡时，系统需要处理冲突。

第一期规则：

- 用户可以选择"作为新角色加载"。
- 用户可以选择"替换项目内某个角色"。
- 系统不自动合并两个角色。
- 如果同一角色卡已经加载到当前项目，系统不能再次作为新角色加载，只能提示已加载或要求用户选择替换已有项目角色快照。
- 如果角色名重复，系统提示用户确认。

角色卡加载后，项目内角色快照成为当前项目的依据。后续修改应发生在项目内快照上。

验收标准：

- 角色名重复时，系统不会静默覆盖已有角色。
- 同一来源角色卡重复加载时，系统不会创建第二个项目角色快照。
- 用户明确选择替换后，才更新对应项目内角色快照。
- 作为新角色加载时，已有角色不受影响。

## 7. 数据对象

### 7.1 CharacterCard

表示角色卡库中的原始角色卡资产。

字段建议：

- id
- name
- gender
- role_type
- identity
- background
- personality
- goal
- motivation
- secret
- conflict_points
- relationship_notes
- speech_style
- catchphrases
- emotional_arc
- story_function
- visual_description
- image_keywords
- reference_image_url
- reference_local_path
- version
- status
- created_at
- updated_at

字段说明：

- `role_type` 在第一期新流程中表示人物原型，例如复仇者、守护者、操控者、成长型、权力型、治愈型。
- `goal` 在第一期新流程中表示核心欲望 / 人物执念。
- `motivation`、`secret`、`conflict_points`、`relationship_notes`、`emotional_arc`、`story_function` 为旧版兼容字段。新建和编辑角色卡时不再推荐填写，旧数据保留但不作为新流程输入。

### 7.2 ProjectCharacterSnapshot

表示角色卡加载到项目后的项目内副本。

字段建议：

- id
- project_id
- source_character_card_id
- source_version
- name
- gender
- role_type
- snapshot_content
- visual_description
- reference_image_url
- reference_local_path
- loaded_at
- updated_at

规则：

- 项目生成任务读取该快照，不直接读取 `CharacterCard` 原文。
- 修改该快照不影响资产库原始角色卡。

## 8. 状态规则

角色卡状态包括：

- draft：草稿。
- active：可加载。
- archived：已归档。

规则：

- 只有 `active` 角色卡可以被加载到项目。
- `archived` 角色卡不再作为新项目可选项。
- 已归档角色卡不应从历史项目来源记录中删除。
- 角色核心设定、视觉描述或参考图发生变化时，应提升版本号。
- 删除已被项目加载过的角色卡风险较高，第一期使用归档代替硬删除。

## 9. 生成引用规则

角色卡库原始内容不直接参与生成。项目生成任务应读取项目内角色快照。

当项目已加载角色卡时：

- 整体故事大纲应基于项目内角色快照中的人物原型和核心欲望，再在项目内生成具体剧情目标、关系和冲突。
- 人物设定生成应优先保留项目内角色快照中的性别、核心身份、人物原型、核心欲望和视觉描述。
- 人物示意图生成应优先使用项目内角色快照中的视觉描述和形象关键词。
- 分集大纲应围绕项目内补充的角色目标、矛盾和关系推进。
- 单集剧本对白应参考角色口吻和说话方式。

当项目未加载角色卡时：

- 系统仍可根据故事大纲自动生成角色。
- 用户可以后续再加载角色卡，但需要提示已有角色设定可能需要合并或替换。

## 10. 合并与冲突规则

当项目中已有角色设定，再加载角色卡时，可能出现冲突。

第一期采用简单处理：

- 用户可以选择"作为新角色加载"。
- 用户可以选择"替换项目内某个角色"。
- 系统不自动合并两个角色。
- 如果角色名重复，系统提示用户确认。

角色卡加载后，项目内角色快照成为当前项目的依据。后续修改应发生在项目内快照上。

1. 作为个人短剧创作者，我想创建角色卡，以便沉淀可复用人物设定。

3. 作为个人短剧创作者，我想维护人物原型和核心欲望，以便后续项目能基于稳定人物资产继续创作。
4. 作为个人短剧创作者，我想把具体人物关系、冲突和反转放在项目内塑造，以便同一角色能复用于不同故事。
5. 作为个人短剧创作者，我想角色卡加载到项目后生成快照，以便当前项目可以独立调整剧情设定。
6. 作为个人短剧创作者，我想维护角色说话方式，以便剧本对白更符合角色。
7. 作为个人短剧创作者，我想维护视觉描述和形象关键词，以便后续生成人物示意图。

9. 作为个人短剧创作者，我想搜索和筛选角色卡，以便快速找到可复用角色。
10. 作为个人短剧创作者，我想把角色卡加载到项目中，以便当前项目基于已有角色继续创作。
11. 作为个人短剧创作者，我想在项目内修改已加载角色，以便适配当前项目。
12. 作为个人短剧创作者，我想项目内修改不影响原始角色卡，以便保护可复用资产。
13. 作为个人短剧创作者，我想同一角色卡可以加载到多个项目，以便复用系列角色。
14. 作为个人短剧创作者，我想归档不再使用的角色卡，以便保持资产库清晰。
15. 作为个人短剧创作者，我想角色名重复时被提醒，以便避免误覆盖项目内已有角色。

## 12. 实现决策

- 角色卡库是项目外资产库，不隶属于单个短剧项目。
- 角色卡库只保存跨项目稳定的人物资产，不保存具体项目剧情安排。
- 角色卡加载到项目后采用快照副本模型，不采用实时共享引用模型。
- 项目生成任务读取项目内角色快照，不直接读取角色卡库原始内容。
- `role_type` 作为兼容字段继续使用，但产品文案统一为"人物原型"。
- `goal` 作为兼容字段继续使用，但产品文案统一为"核心欲望 / 人物执念"。
- 旧版剧情字段保留用于历史兼容，不做破坏性数据库迁移。
- 第一版使用归档代替硬删除。
- 第一版不做自动同步、差异对比和多人共享。
- 第一版冲突处理采用显式选择：作为新角色加载或替换项目内角色。
- 角色卡支持参考图上传和人物三视图生成，但不做专业角色一致性训练。

## 13. 验收标准

- 用户可以创建角色卡。
- 用户可以编辑角色基础信息、人物原型、核心欲望、口吻和视觉描述。
- 用户创建或编辑角色卡时必须选择性别，性别仅支持男或女。
- 用户可以上传参考图并保存图片引用。
- 用户可以在列表中搜索和筛选角色卡。
- 只有 `active` 角色卡可以被加载到项目。
- 加载到项目后生成项目内快照，并保留来源 ID 和来源版本。
- 同一角色卡可以加载到多个项目。
- 修改项目内角色快照不影响角色卡库原始内容。
- 修改角色卡库原始内容不自动覆盖项目内快照。
- 角色名重复时，系统提示用户确认，不静默覆盖。
- 已归档角色卡不再作为新项目可选项，但历史项目来源仍可追踪。

## 14. 非目标

- 不做角色一致性训练。
- 不做专业角色一致性训练。
- 不做复杂人物关系图。
- 不做多角色对话模拟。
- 不做角色卡版本差异对比。
- 不做自动同步到已加载项目。
- 不做多人协作和权限控制。

## 15. 后续扩展

- 支持角色卡版本差异对比。
- 支持从项目内角色另存为新角色卡。
- 支持人物关系图。
- 支持角色对白样例库。
- 支持角色参考图多版本管理。
- 支持基于角色卡的多角色对话测试。
