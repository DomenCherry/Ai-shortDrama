## 1. 功能定位

项目管理是第一期的入口功能。它负责让用户先进入统一的项目管理页，查看已有短剧项目，再从项目管理页创建新项目，并在项目开始时明确短剧的基础创作约束，包括题材、平台、集数、单集时长和总时长。

该功能的核心价值是：

- 让用户把一个短剧想法沉淀为可管理的项目。
- 让用户先看到已有项目和项目状态，再决定继续已有项目或创建新项目。
- 在生成任何 AI 内容前，先确定短剧体量。
- 防止项目规模失控，确保后续选题、故事大纲、人物、分集和剧本生成都围绕同一套项目约束进行。
- 创建项目后直接进入项目工作台；项目工作台通过“项目资料 / 资产、故事文本、短剧制作”三个入口继续维护基础信息、资产、故事文本、剧本、分镜与文案。

用户还可以输入一段自然语言创意描述，说明想做什么类型的短剧。系统应基于创意描述提取或推断题材、主线冲突、目标平台、可能的受众、情绪基调、主要卖点和建议集数与单集时长。从创意中推断出的集数和单集时长仍必须满足项目时长规则。

### 默认决策

- 第一期仅支持本地或单用户项目，不做多用户协作。
- 项目名称可以由用户手动输入，也可以根据创意自动生成。
- 目标平台可先支持通用文本输入，后续再做枚举选项。
- 如果用户未填写集数，默认生成 20 集。
- 如果用户未填写单集时长，默认 1 分钟。

## 2. 目标用户

核心用户是个人短剧创作者。

用户通常只有一个初步想法，例如"都市逆袭爽剧"或"古装重生复仇"，但还没有完整项目结构。项目创建页需要帮助用户快速录入基本信息，而不是要求用户一次性填完所有专业设定。

## 3. 功能目标

用户完成该功能后，系统应获得一个合法、可保存、可继续生成内容的短剧项目。

必须达成：

- 用户可以通过左侧"项目管理"进入项目列表。
- 左侧导航不再提供独立的"创建项目"一级入口。
- 用户可以在项目管理页查看已有项目。
- 用户可以创建新项目。
- 用户可以录入创意描述和基础信息。
- 用户可以设置集数和单集时长。
- 系统自动计算总时长。
- 系统强校验单集时长和总时长。
- 合法项目可以保存。
- 非法项目不能保存，也不能进入后续 AI 生成流程。
- 用户后续可以返回并编辑项目基础信息。

## 4. 字段设计

### 4.1 Project

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| id | string | 是 | 自动生成 | 项目唯一标识 |
| title | string | 否 | 根据创意自动生成或"未命名短剧" | 项目名称 |
| idea | string | 是 | 无 | 创意描述 |
| target_platform | string | 否 | 抖音 | 目标平台，第一期先允许文本输入 |
| genre | string | 否 | 无 | 题材类型 |
| episode_count | integer | 是 | 20 | 集数 |
| episode_duration | number | 是 | 1 | 单集时长，单位分钟 |
| total_duration | number | 是 | 自动计算 | 总时长，单位分钟 |
| target_audience | string | 否 | 无 | 目标受众 |
| style | string | 否 | 无 | 内容风格 |
| remark | string | 否 | 无 | 备注 |
| status | string | 是 | draft | 项目状态 |
| created_at | datetime | 是 | 自动生成 | 创建时间 |
| updated_at | datetime | 是 | 自动更新 | 更新时间 |

### 4.2 字段说明

**项目名称（title）：**

- 用户可以手动输入。
- 如果用户未输入，系统可以先保存为"未命名短剧"。
- 后续选题策划生成后，用户可以从剧名候选中选择一个作为项目名称。

**创意描述（idea）：**

- 必填。
- 用于后续选题策划生成。
- 建议最少 10 个中文字符。
- 为空时不能创建项目。
- 系统可基于创意描述提取或推断题材、主线冲突、目标平台、可能的受众、情绪基调、主要卖点、建议集数和单集时长。

**目标平台（target_platform）：**

- 第一期先使用文本输入或简单选项。
- 推荐默认值为"抖音"。
- 后续可以扩展为抖音、快手、小红书、视频号、B 站等枚举。

**题材类型（genre）：**

- 第一期可以使用文本输入。
- 可提示示例：都市逆袭、古装重生、豪门恩怨、悬疑反转、甜宠、复仇爽剧。

**集数（episode_count）：**

- 必填。
- 必须为正整数。
- 默认值为 20。
- 不单独限制最大集数，但必须满足总时长不超过 240 分钟。

**单集时长（episode_duration）：**

- 必填。
- 单位为分钟。
- 必须大于 0。
- 必须小于或等于 2。
- 默认值为 1。
- 支持小数，例如 0.5 表示 30 秒，1.5 表示 90 秒。

**总时长（total_duration）：**

- 由系统实时计算。
- 不允许用户直接编辑。
- 计算公式：`total_duration = episode_count * episode_duration`。
- 必须大于 0 且小于或等于 240 分钟。

**项目状态（status）：**

- `draft`：刚创建，尚未生成选题策划。
- `planning`：已进入选题策划或整体故事设计。
- `writing`：已进入分集大纲或剧本阶段。
- 第一期可以只实现 `draft`，但数据结构预留后续状态。

**数据约束：**

- `episode_count` 必须为正整数。
- `episode_duration` 必须大于 0 且不超过 2。
- `total_duration = episode_count * episode_duration`。
- `total_duration` 必须大于 0 且不超过 240。

## 5. 校验规则

### 5.1 必填校验

以下字段必须满足：

- 创意描述不能为空。
- 集数不能为空。
- 单集时长不能为空。

### 5.2 类型校验

集数：

- 必须是整数。
- 必须大于 0。

单集时长：

- 必须是数字。
- 必须大于 0。
- 允许小数。

### 5.3 范围校验

单集时长：

```text
0 < episode_duration <= 2
```

总时长：

```text
0 < episode_count * episode_duration <= 240
```

### 5.4 强校验策略

当项目不满足时长规则时：

- 禁止保存项目。
- 禁止进入后续 AI 生成流程。
- 在创建页或编辑页展示明确错误。

系统不自动修改用户输入的集数或时长。

### 5.5 错误提示

| 场景 | 提示文案 |
| --- | --- |
| 创意描述为空 | 请先输入短剧创意描述 |
| 集数为空 | 请填写短剧集数 |
| 集数不是正整数 | 集数必须是大于 0 的整数 |
| 单集时长为空 | 请填写单集时长 |
| 单集时长小于或等于 0 | 单集时长必须大于 0 分钟 |
| 单集时长超过 2 分钟 | 单集时长不能超过 2 分钟 |
| 总时长超过 240 分钟 | 总时长不能超过 240 分钟，请减少集数或单集时长 |

## 6. 状态与边界情况

### 6.1 空项目列表

当没有项目时：

- 展示空状态。
- 引导用户创建第一个短剧项目。

### 6.2 未命名项目

当用户未填写项目名称：

- 系统保存为"未命名短剧"。
- 后续用户可以编辑。
- 后续选题策划生成剧名候选后，用户可以选择剧名替换项目名称。

### 6.3 小数时长

单集时长允许小数。

示例：

- `0.5` 表示 30 秒。
- `1.5` 表示 90 秒。

展示时建议同时显示分钟和秒：

```text
单集 1.5 分钟，约 90 秒
```

### 6.4 边界值

合法边界：

- 1 集，每集 0.1 分钟。
- 120 集，每集 2 分钟，总时长 240 分钟。
- 240 集，每集 1 分钟，总时长 240 分钟。

非法边界：

- 0 集。
- -1 集。
- 每集 0 分钟。
- 每集 2.01 分钟。
- 121 集，每集 2 分钟。

## 7. 后续模块依赖

项目创建成功后，后续模块都应引用 Project 中的基础信息。

选题策划生成依赖：

- 创意描述。
- 目标平台。
- 题材类型。
- 集数。
- 单集时长。
- 总时长。
- 目标受众。
- 内容风格。

整体故事大纲生成依赖：

- 项目基础信息。
- 选题策划。
- 总时长限制。

分集大纲生成依赖：

- 集数。
- 单集时长。
- 总时长。
- 整体故事大纲。
- 人物设定。

单集剧本生成依赖：

- 单集时长。
- 当前集数大纲。
- 人物设定。
- 整体故事大纲。

```markdown
- 集数：20 集
- 单集时长：1 分钟
- 总时长：20 分钟
- 目标受众：xxx
- 内容风格：xxx
- 备注：xxx
```

## 9. 用户故事

1. 作为个人短剧创作者，我想创建一个短剧项目，以便集中管理这个项目的所有创作资料。
2. 作为个人短剧创作者，我想输入一个自然语言创意，以便系统理解我想创作的故事方向。
3. 作为个人短剧创作者，我想配置目标平台和集数，以便生成内容更符合发布场景。
4. 作为个人短剧创作者，我想配置单集时长，以便控制每集短剧的内容密度。
5. 作为个人短剧创作者，我想看到总时长，以便判断整部短剧的制作规模。
6. 作为个人短剧创作者，我想在时长超限时被阻止保存，以便避免项目规模失控。

## 10. 实现决策

### 来自 features/ §12

第一期可以先将该功能实现为单用户项目管理能力。

建议优先级：

1. 左侧导航合并为单一"项目管理"入口。
2. 项目列表页。
3. 项目创建页。
4. 项目基础字段保存。
5. 时长实时计算。
6. 时长强校验。
7. 项目基础信息编辑。
8. Markdown 导出中的基础信息部分。

不要在该功能中提前实现：

- 账号系统。
- 团队权限。
- 复杂平台枚举管理。
- 自动推荐最佳集数。
- 自动修正用户输入时长。

### 来自 prd.md §14（项目相关决策）

- 第一期以单用户本地项目或单用户工作台为核心，不做账号体系。
- 第一期主数据库确定为 PostgreSQL，本地开发通过 Docker Compose 启动。
- 单集时长超过 2 分钟或总时长超过 240 分钟时，采用强校验：阻止保存和生成。
- 项目工作台内创作产物使用 `draft`、`confirmed`、`needs_review` 状态管理；上游内容变更时标记下游内容需要检查，不自动覆盖用户已编辑内容。
- 数据应尽量结构化，避免只保存一整段不可解析文本。
- Markdown 导出作为第一期唯一必须支持的导出格式。
- 版本记录先做轻量历史，不做复杂协同编辑和差异对比。
- 项目工作台 v1 先支持人工维护项目资料 / 资产、故事文本和短剧制作文本，不要求接入 AI 生成。
- 项目工作台 v1 支持在工作台内直接选择并加载世界观和角色卡，用户无需跳转到资产库页面即可完成资产加载。
- 世界观和角色卡加载到项目后采用快照副本模型，不采用实时共享引用模型。
- 每个项目最多加载一个项目世界观；项目角色可以加载多个，但同一角色卡不能重复加载到同一项目。
- 项目世界观和项目角色可以在当前项目内微调，微调只更新项目快照，不回写世界观库或角色卡库原始内容。
- 项目内快照优先于资产库原文参与生成；资产库原文更新不自动覆盖项目快照。
- 故事文本包含整体故事大纲、分集大纲和单集内容；短剧制作包含单集剧本、分镜镜头、字幕和发布文案。
- 短剧制作阶段只能沿用项目资料 / 资产和故事文本，不能直接修改世界观或角色；如需修改，用户必须回到上游区域调整。
- 后续生成应优先使用用户确认后的最新内容。
- 所有 AI 生成文本结果都必须可编辑。

## 11. 验收标准

### 来自 features/ §11

#### 正常创建项目

输入：

- 创意描述：都市逆袭爽剧，女主被丈夫背叛后发现自己是豪门继承人。
- 集数：20。
- 单集时长：1。

预期：

- 总时长显示为 20 分钟。
- 项目保存成功。
- 用户进入项目工作台。

#### 总时长等于上限

输入：

- 集数：120。
- 单集时长：2。

预期：

- 总时长显示为 240 分钟。
- 项目允许保存。

#### 总时长超过上限

输入：

- 集数：121。
- 单集时长：2。

预期：

- 总时长显示为 242 分钟。
- 项目不允许保存。
- 显示提示：总时长不能超过 240 分钟，请减少集数或单集时长。

#### 单集时长超过上限

输入：

- 集数：20。
- 单集时长：2.5。

预期：

- 项目不允许保存。
- 显示提示：单集时长不能超过 2 分钟。

#### 集数非法

输入：

- 集数：0。
- 单集时长：1。

预期：

- 项目不允许保存。
- 显示提示：集数必须是大于 0 的整数。

#### 创意描述为空

输入：

- 创意描述为空。
- 集数：20。
- 单集时长：1。

预期：

- 项目不允许保存。
- 显示提示：请先输入短剧创意描述。

#### 小数时长

输入：

- 集数：30。
- 单集时长：1.5。

预期：

- 总时长显示为 45 分钟。
- 单集时长可显示为 1.5 分钟，约 90 秒。
- 项目允许保存。

### 来自 prd.md §9.3/§9.4

- 用户可以创建项目。
- 用户可以查看已创建项目。
- 用户可以编辑项目基础信息。
- 项目内容刷新页面后不丢失。
- 输入 121 集、每集 2 分钟时，系统阻止保存，因为总时长为 242 分钟。
- 输入每集 2.5 分钟时，系统阻止保存，因为单集超过 2 分钟。
- 输入 120 集、每集 2 分钟时，系统允许保存，因为总时长为 240 分钟。
- 用户可以保存创意描述。
- 系统可以基于创意描述生成后续内容。
- 用户可以修改创意描述并重新生成后续内容。
- 从创意中推断出的集数和单集时长仍必须满足项目时长规则。
