# 模块 PRD：模型 API 配置与连通性测试

## 1. 功能定位

"模型 API 配置与连通性测试"是第一期的基础配置能力。它负责让用户配置自己的文本生成模型 API 和图片生成模型 API，并在使用前通过手动测试确认接口是否可用。

配置中心应以用户自定义模型为核心，不绑定单一供应商。系统可以提供常用供应商预设来减少填写成本，但用户仍应能够手动配置其他兼容或非兼容供应商。

该功能不是一个创作模块，但它是后续 AI 生成能力的前置条件：

- 文本生成模型用于生成选题策划、整体故事大纲、人物设定、分集大纲、单集剧本和改写内容。
- 图片生成模型用于生成人物示意图、角色三视图等图片生成任务。

## 2. 功能目标

用户完成该功能后，系统应知道应该调用哪个文本模型和哪个图片模型，并能确认接口处于可用状态。

必须达成：

- 用户可以保存文本生成模型配置。
- 用户可以保存图片生成模型配置。
- 用户可以通过供应商预设快速创建图片模型配置。
- 用户可以通过自定义配置接入其他图片模型供应商。
- 用户可以分别测试文本模型和图片模型。
- 系统可以展示测试成功或失败状态。
- 测试失败时，系统可以给出可理解的失败原因。
- 未配置或测试不可用时，系统阻止对应生成任务。
- API Key 不在普通页面明文展示，也不进入 Markdown 导出。
- 用户可以查看历史上保存过的所有模型配置。
- 用户可以编辑已有配置。
- 用户可以删除不再使用的配置。
- 用户可以在多个已保存配置之间切换启用/停用。

### 3.2 last_test_status 状态

可选状态：

- `untested`：已保存但未测试。
- `success`：最近一次测试成功。
- `failed`：最近一次测试失败。

| --- | --- | --- | --- | --- |

| config_type | string | 是 | 无 | `text` 或 `image` |
| request_summary | string | 否 | 无 | 脱敏后的测试请求摘要 |
| success | boolean | 是 | 无 | 是否成功 |
| response_summary | string | 否 | 无 | 脱敏后的响应摘要 |
| error_message | string | 否 | 无 | 失败原因 |
| latency_ms | integer | 否 | 无 | 接口耗时 |
| tested_at | datetime | 是 | 自动生成 | 测试时间 |

## 4. 校验规则

### 4.1 通用校验

保存配置时必须校验：

- 供应商名称不能为空。
- API Base URL 不能为空。
- API Key 不能为空。
- 模型名称不能为空。

API Base URL 应至少满足：

- 以 `http://` 或 `https://` 开头。
- 不能包含明显空格。

API Key 展示规则：

- 已保存的 API Key 默认脱敏展示。
- 用户无法直接查看完整 API Key。
- 用户可以重新输入新的 API Key 覆盖旧值。

### 4.2 图片配置校验

图片尺寸不能为空。

第一期不强制校验所有供应商的尺寸合法性，只需要保存用户输入或选项值。具体尺寸是否被供应商支持，由连通性测试返回结果判断。

当用户选择供应商预设时：

- `provider_preset` 必须是系统已支持的预设标识。
- 系统应自动填充默认 API Base URL、接口路径和参考图能力。
- 用户可以修改模型名称、图片尺寸和备注。

当用户选择自定义配置时：

- 供应商名称、API Base URL、API Key、模型名称仍由用户手动填写。
- 是否支持参考图输入由用户配置或后续测试结果确认。
- 系统不假设自定义供应商一定兼容某个固定协议。

### 4.3 编辑后重置测试状态

编辑并保存已有配置后，该配置的 `last_test_status` 必须重置为 `untested`，以避免用户修改了 API Key 或模型名称后仍显示旧的测试通过状态。

### 4.4 删除规则

- 删除配置不物理删除数据库记录，避免破坏测试日志外键引用。
- 已删除配置不在配置列表展示，不允许编辑、测试或设为启用。
- 删除当前启用的唯一配置是允许的；删除后该类型没有启用配置，生成任务应引导用户重新配置模型。

### 4.5 启用/停用规则

- 同一 `config_type` 下最多只有一条 `enabled=true` 的配置。
- 将某条配置设为启用时，系统应自动将该 `config_type` 下其他配置设为 `enabled=false`。

## 5. 连通性测试设计

### 5.1 文本模型测试

测试输入建议：

```text
请返回一句不超过 10 个字的中文短句：接口可用。
```

成功判断：

- 接口返回成功状态。
- 响应中包含可解析的文本内容。
- 文本内容不为空。

失败判断：

- 网络不可达。
- API Key 无效。
- 模型名称不存在。
- 响应超时。
- 响应格式无法解析。
- 额度不足或权限不足。

### 5.2 图片模型测试

测试提示词建议：

```text
一张简单的角色头像示意图，年轻女性，现代都市风格，干净背景。
```

成功判断：

- 接口返回成功状态。
- 响应中包含图片 URL、图片文件、本地路径或可解析的图片结果。
- 图片结果可以被系统记录。
- 对声明支持参考图输入的图片配置，后续角色三视图生成可以携带已上传参考图；第一期连通性测试可以先使用轻量文生图请求验证基础可用性。

失败判断：

- 网络不可达。
- API Key 无效。
- 模型名称不存在。
- 图片尺寸不支持。
- 供应商预设和实际接口协议不匹配。
- 参考图输入参数不支持。
- 响应超时。
- 响应格式无法解析。
- 额度不足或权限不足。

### 5.3 测试结果记录

每次测试后都应更新：

- `last_test_status`。
- `last_tested_at`。
- `last_test_error`。

同时新增一条 `ModelApiTestLog`。

## 6. 生成任务拦截规则

文本生成任务包括：

- 选题策划生成。
- 整体故事大纲生成。
- 人物设定生成。
- 分集大纲生成。
- 单集剧本生成。
- 文本改写。

执行这些任务前必须满足：

- 存在当前启用的文本模型配置。
- 该启用配置的最近测试状态为 `success`。

图片生成任务包括：

- 人物示意图生成。
- 人物示意图重新生成。
- 角色三视图生成。
- 角色三视图重新生成。

执行这些任务前必须满足：

- 存在当前启用的图片模型配置。
- 该启用配置的最近测试状态为 `success`。

如果生成任务需要上传参考图参与生成，还应满足：

- 当前启用的图片模型配置声明支持参考图输入。
- 当前角色已上传可读取的参考图。

如果不满足条件，系统应阻止生成，并引导用户进入设置页。

> 拦截规则基于「当前启用的配置」及其测试状态，而非历史上所有配置。同一 `config_type` 下只有被标记为 `enabled=true` 的配置才会被用于生成任务拦截判断。

## 7. 安全要求

- API Key 不写入 Markdown 导出。
- API Key 不在列表、卡片、普通文本中明文展示。
- 测试日志中不保存完整 API Key。
- 错误日志中不展示完整 API Key。
- 如果后续实现为 Web 应用，API Key 不应暴露到前端可读取的持久化存储中。

## 9. 验收用例

### 9.1 保存文本模型配置

输入：

- 供应商名称：自定义文本模型。
- API Base URL：`https://api.example.com/v1`。
- API Key：有效密钥。
- 模型名称：`text-model`。

预期：

- 配置保存成功。
- API Key 脱敏展示。
- 状态为已配置，未测试。

### 9.2 文本模型测试成功

前置条件：

- 已保存可用文本模型配置。

预期：

- 点击测试连接后，系统调用文本接口。
- 测试成功。
- 显示最近测试时间。
- 文本生成任务可用。

### 9.3 文本模型测试失败

输入：

- API Key 错误或模型名称错误。

预期：

- 测试失败。
- 显示明确失败原因。
- 文本生成任务不可用。

### 9.4 保存图片模型配置

输入：

- 供应商名称：自定义图片模型。
- API Base URL：`https://api.example.com/v1`。
- API Key：有效密钥。
- 模型名称：`image-model`。
- 图片尺寸：`1024x1024`。

预期：

- 配置保存成功。
- API Key 脱敏展示。
- 状态为已配置，未测试。

### 9.5 保存火山方舟 Seedream 图片模型预设

输入：

- 配置方式：供应商预设。
- 供应商预设：火山方舟 Seedream。
- API Key：有效火山方舟密钥。
- 模型名称：用户实际开通的 Seedream 模型。

- 系统记录接口路径：`/images/generations`。
- 系统记录该配置支持参考图输入。

## 10. 实现决策

- 第一期包含模型 API 配置能力，支持用户配置自己的文本生成模型和图片生成模型。
- 图片模型配置以多供应商可扩展为目标，支持供应商预设和自定义配置。
- 火山方舟 Seedream 可作为第一批图片模型预设，但系统不能依赖单一供应商。
- 文本模型和图片模型独立配置、独立测试、独立启用。
- 文本生成任务依赖可用的文本模型配置，人物示意图生成依赖可用的图片模型配置。
- API Key 不进入 Markdown 导出，不在普通页面明文展示。

## 11. 实现建议

建议优先级：

1. 设置页入口。
2. 文本模型配置保存。
3. 图片模型自定义配置保存。
4. 图片模型供应商预设选择。
5. 火山方舟 Seedream 预设。
6. 文本模型测试按钮。
7. 图片模型测试按钮。
8. 测试状态记录。
9. 生成任务前置拦截。

第一期暂不做：

- 完整多供应商模板库。
- 多个文本模型之间的自动路由。
- 多个图片模型之间的自动路由。
- 团队级 API Key 管理。
- 用量统计和费用分析。
- 自动定时健康检查。
- 配置列表分页（如配置数量极大）。
