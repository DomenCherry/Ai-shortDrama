# 增量 PRD：剧本来源正文快速参考

> 状态：**已确认，待实现**

## Problem Statement

单集故事正文是结构化剧本的直接内容来源，但用户进入剧本工作台后只能看到正文状态，无法直接阅读正文。为了核对情节、动作、对白来源，用户必须跳转到故事文本模块，再返回剧本工作台并恢复编辑位置。这个往返打断了剧本拆场和改写流程，也增加了遗漏原文信息的风险。

## Solution

在结构化剧本工作台右侧检查区增加“来源正文”视图，只读展示当前选中集的完整故事正文。

该视图与当前集数同步，展示正文标题、状态、字数和正文内容，并提供“前往编辑正文”入口。用户可以在不离开剧本工作台的情况下对照正文；需要修改来源时，仍回到故事文本模块完成，保持上游内容与下游剧本的职责边界。

桌面端使用现有右侧面板，不使用弹窗。窄屏下随现有检查区移动到剧本编辑区下方，避免遮挡编辑内容。

## User Stories

1. 作为短剧创作者，我希望在编辑剧本时查看当前集完整故事正文，以便核对剧本是否覆盖了关键情节。
2. 作为短剧创作者，我希望正文参考随剧本集数同步切换，以免误看其他集内容。
3. 作为短剧创作者，我希望看到来源正文的标题、状态和字数，以便判断来源是否完整、是否需要复核。
4. 作为短剧创作者，我希望正文保持原有换行和段落，以便快速扫描故事结构。
5. 作为短剧创作者，我希望能够滚动查看长正文，同时不让整个右侧面板无限增长。
6. 作为短剧创作者，我希望展开或收起正文参考，以便在阅读原文与查看检查结果之间分配空间。
7. 作为短剧创作者，我希望从参考区前往正文编辑页面，以便在发现来源问题时修改上游内容。
8. 作为短剧创作者，我希望剧本工作台中的正文保持只读，以免误改来源并触发不可预期的下游状态变化。
9. 作为短剧创作者，我希望正文缺失时看到明确说明和创建入口，而不是空白面板。
10. 作为短剧创作者，我希望查看正文不会改变当前剧本草稿或未保存状态。
11. 作为键盘用户，我希望正文参考区和跳转操作可以正常获得焦点并具有明确标签。
12. 作为窄屏用户，我希望正文参考不会压缩剧本编辑器到不可用宽度。

## Implementation Decisions

- 修改结构化剧本工作台右侧检查区，增加独立的“来源正文”区块。
- 复用工作台已经加载的当前集故事正文，不新增数据库字段或后端 API。
- 来源正文只读；编辑继续由故事文本模块负责。
- 正文区默认展开，用户可折叠；折叠状态仅为当前页面本地状态，不持久化。
- 正文内容保留换行，正文容器设置最大高度并独立滚动。
- 元信息展示当前集、正文标题、状态和按非空白字符计算的字数。
- “前往编辑正文”携带当前集数，确保落到相同单集。
- 缺少正文时展示空状态、原因说明和创建正文入口。
- 保留现有“结构与一致性”和“候选历史”能力，不改变生成、保存、确认或版本规则。
- 不抽取新的共享业务模块；正文参考是纯展示组件，输入为当前集正文、集数和项目 ID，便于独立维护。

## Testing Decisions

- 测试外部可见行为，不依赖组件内部 state 或 DOM 实现细节。
- 当前项目未配置前端组件测试框架，本次使用 TypeScript 类型检查、Lint 和浏览器人工验收。
- 验证存在正文、缺少正文、正文需要检查、长正文滚动、集数切换和窄屏布局。
- 验证查看、展开、折叠正文不会改变剧本未保存状态。
- 验证“前往编辑正文”包含当前集参数。
- 后续引入组件测试框架后，为只读正文参考组件补充渲染与空状态测试。

## Out of Scope

- 在剧本工作台直接编辑或保存故事正文。
- 自动建立正文段落与剧本场次、内容块之间的映射。
- 点击场次后自动高亮对应正文段落。
- 正文与剧本的逐字差异比较。
- 新增正文版本接口或修改后端状态传播规则。
- 持久化用户的展开、折叠或滚动位置。

## Further Notes

- 当前工作台已持有当前集故事正文，本功能属于前端信息架构优化。
- 若后续需要场次与正文联动，应先定义稳定的来源片段 ID，避免使用脆弱的文本匹配。
