# 模块 PRD：制作包导出

> 状态：**模块边界已确认，待详细设计**

## 1. 问题陈述

剧本、分镜、镜头视频结果和后期资料分散在不同数据对象中，创作者缺少一个可校验、可版本化并能直接交给外部制作工具或人员使用的统一交付物。

## 2. 解决方案

对单集生产资料执行完整性检查，按选定格式组装成带版本和来源信息的标准化制作包。

## 3. 输入与输出

输入：结构化剧本、分镜及提示词、已采用的镜头视频结果、后期资料、人物与场景参考素材。

输出目录建议：

```text
第01集-制作包/
├── 01-结构化剧本.md
├── 02-分镜表.xlsx
├── 03-AI提示词.xlsx
├── 04-配音稿.md
├── 05-字幕.srt
├── 06-剪辑说明.md
├── 07-发布文案.md
├── production.json
├── videos/
│   └── S01-001.mp4
└── references/
    ├── characters/
    └── scenes/
```

## 4. 功能范围

- 展示导出前完整性检查结果。
- 区分阻塞错误、风险警告和一般提示。
- 选择需要导出的内容和格式。
- 生成 Markdown、Excel、JSON 和 SRT。
- 收集已采用的镜头视频结果引用；如素材已下载到本地，可按镜头编号复制到 `videos/`。
- 收集人物和场景参考素材。
- 按统一规则生成目录和文件名。
- 保存制作包版本、生成时间和来源版本。
- 查看历史制作包并重新生成。
- 上游变化后标记历史制作包为过期或需要检查。

## 6. 导出格式职责

- Markdown：供创作者、编剧、配音和剪辑人员阅读。
- Excel：供镜头生产、提示词管理和批量人工调整。
- JSON：供外部工具、自动化脚本和后续系统集成。
- SRT：供剪映等剪辑软件导入字幕。
- videos：保存或引用已采用的镜头视频素材，供剪辑软件整理使用。
- references：收集已确认的人物与场景一致性素材。

## 7. 状态与依赖

- 只有通过阻塞性检查的内容才能生成正式制作包。
- 用户可以选择带警告导出，但制作包必须记录警告快照。
- 任一来源模块变化后，已有制作包标记为需要检查或已过期。
- 重新生成创建新版本，不覆盖历史制作包记录。

## 8. 用户故事

1. 作为短剧创作者，我想在导出前检查缺失内容，以免把不完整资料交给外部工具。
2. 作为短剧创作者，我想一次获得剧本、分镜、提示词、字幕和剪辑说明，以便开始制作。
3. 作为 AI 视频创作者，我想获得结构化 JSON、Excel 和已采用视频素材清单，以便进行批量整理和自动化处理。
4. 作为剪辑人员，我想获得 SRT 和规范的素材目录，以便快速导入和整理。
5. 作为短剧创作者，我想保留历史制作包，以便追溯某次交付使用的内容版本。

## 9. 验收标准

- 系统可以识别阻塞错误、警告和提示。
- 系统可以按单集生成完整制作包。
- 导出文件名、目录和内容符合统一规则。
- JSON、Excel、Markdown 和 SRT 包含对应模块的有效内容。
- 已采用视频素材进入制作包清单；素材无法复制时，制作包记录可追溯的结果引用和风险提示。
- 制作包记录所有来源版本和生成时间。
- 上游变化后历史制作包状态正确更新。
- 重新生成不会覆盖历史版本。

## 10. 测试决策

- 重点测试校验规则、文件命名、目录清单、来源追溯和版本不可覆盖。
- 对 JSON、SRT 和 Excel 验证可解析性和关键字段完整性。
- 测试缺失参考素材、超长文件名、空模块和部分格式导出。

## 11. 非目标

- 不在导出阶段直接调用外部视频工具执行生成；视频生成由分镜模块负责。
- 不上传制作包到第三方平台。
- 不生成完整视频成片。
- 不保证第三方工具长期兼容性。

## 12. 待细化问题

- 阻塞错误和警告的完整规则表。
- 制作包版本号与存储策略。
- Excel 工作表和 JSON Schema。
- 参考素材复制、链接和缺失处理规则。
- 导出任务的同步或异步执行方式。
