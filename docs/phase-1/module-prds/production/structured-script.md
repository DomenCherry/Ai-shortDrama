# 模块 PRD：结构化剧本

> 状态：**模块边界已确认，详细设计进行中**

## 1. 问题陈述

当前单集剧本以场景说明、对白、动作说明和旁白四个大文本字段保存，难以表达内容顺序，也无法稳定支持场次级改写、镜头拆分、配音和字幕生成。

## 2. 解决方案

将单集故事正文转换成由多个场次组成的结构化剧本。每个场次保存场景元信息，并通过有顺序的内容块表达动作、对白、旁白和转场。

## 3. 输入与输出

输入：

- 项目基础信息和目标单集时长。
- 项目世界观与角色快照。
- 整体故事大纲。
- 当前分集大纲。
- 当前单集故事正文。
- 上一集摘要或必要的连续性上下文。

输出：

- 单集结构化剧本。
- 有序场次列表。
- 每个场次的元信息和有序内容块。
- 单集与场次预计时长。
- 可供分镜模块读取的正式剧本版本。

## 4. 功能范围

- 从单集故事正文生成整集候选剧本。
- 预览并采用候选版本。
- 新增、编辑、删除和排序场次。
- 编辑场次元信息。
- 新增、编辑、删除和排序内容块。
- 按场次重新生成或局部改写。
- 检查目标时长、人物口吻和上游一致性。
- 查看历史候选版本。

## 6. 状态与依赖

- 单集故事正文变化后，正式剧本标记为需要检查。
- 剧本采用新候选版本或保存实质变化后，下游分镜、后期准备和制作包标记为需要检查。
- 只有已保存剧本才能进入正式分镜生成。
- 是否要求“已确认”才能生成分镜，待详细设计确认。

## 7. 交互要求

- 按场次组织剧本，场次可折叠。
- 场次元信息直接展示；剧情作用和一致性提示默认折叠。
- 内容块保持明确顺序，不能拆成互不关联的大文本框。
- AI 生成使用候选稿机制，采用前不修改正式剧本。
- 局部生成只更新目标场次或选中内容。
- 删除场次前提示对下游分镜的影响。

## 8. 用户故事

1. 作为短剧创作者，我想从单集故事正文生成结构化剧本，以便进入视频制作。
2. 作为短剧创作者，我想按场次查看剧本，以便快速理解拍摄结构。
3. 作为短剧创作者，我想让动作、对白和旁白保持正确顺序，以便后续准确拆分镜头。
4. 作为短剧创作者，我想编辑单个场次，而不影响其他已确认内容。
5. 作为短剧创作者，我想重新生成不满意的场次，以便降低整集返工成本。
6. 作为短剧创作者，我想检查剧本时长，以便符合项目设置的单集时长。
7. 作为短剧创作者，我想确认候选版本后再覆盖正式剧本，以便保留创作控制权。

## 9. 验收标准

- 系统可以基于当前单集故事正文生成完整候选剧本。
- 候选剧本采用前不影响正式剧本。
- 剧本包含至少一个场次，每个场次包含有序内容块。
- 用户可以新增、编辑、删除和排序场次及内容块。
- 用户可以对单个场次执行重新生成或局部改写。
- 系统显示场次与整集预计时长。
- 保存剧本后正确标记下游内容状态。
- 剧本内容可被分镜模块稳定读取。

## 10. 测试决策

- 测试面向外部行为，不绑定具体页面组件或内部函数。
- 重点覆盖候选版本采用、场次排序、内容块排序、局部改写范围和状态传播。
- 生成失败、空正文、上游缺失和并发保存需要覆盖。

## 11. 非目标

- 不在本模块生成镜头。
- 不生成图片或视频素材。
- 不维护字幕时间轴。
- 不直接适配 Seedance 或剪映格式。

## 12. 待细化问题

- 场次和内容块的最终字段及必填规则。
- 整集生成、场次重写和局部改写的指令模型。
- 时长估算规则。
- 剧本确认与分镜生成之间的门槛。
- 历史版本保留数量和恢复规则。
