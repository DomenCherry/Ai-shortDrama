# 模块 PRD：结构化剧本

> 状态：**详细设计与前后端 Spec 已完成，待实现**

## 1. 问题陈述

当前单集剧本以场景说明、对白、动作说明和旁白四个大文本字段保存，不能表达内容的真实顺序，也无法稳定支持场次级改写、分镜拆分、配音、字幕和版本追溯。

个人短剧创作者需要把单集故事正文转换成结构明确、可人工控制、可局部重新生成并能直接作为分镜输入的生产剧本。

## 2. 解决方案

单集剧本改为三级结构：

```text
单集结构化剧本
  -> 有序场次
     -> 有序内容块（动作 / 对白 / 旁白 / 转场）
```

AI 先生成候选剧本，用户预览并明确采用后才更新正式剧本。正式剧本支持人工编辑、场次级重新生成和选中内容局部改写。

## 3. 输入与输出

### 3.1 输入

- 项目基础信息和目标单集时长。
- 项目世界观快照。
- 项目角色快照及角色口吻。
- 整体故事大纲。
- 当前分集大纲。
- 当前单集故事正文及其版本。
- 上一集摘要或必要的连续性上下文。
- 用户本次生成或改写指令。

### 3.2 输出

- 单集结构化剧本。
- 有序场次列表。
- 每个场次的元信息和有序内容块。
- 自动估算、人工覆盖及最终生效时长。
- 一致性检查结果。
- 可供分镜模块读取并追溯来源的正式剧本版本。

## 4. 功能范围

### 4.1 整集生成

- 基于当前单集故事正文生成整集候选剧本。
- 保存生成时使用的完整输入快照、模型信息和用户指令。
- 候选剧本采用前不修改正式剧本。
- 用户可以预览候选稿与当前正式剧本的差异。
- 用户明确采用后，候选稿成为新的正式剧本版本。

### 4.2 人工编辑

- 新增、编辑、删除和排序场次。
- 编辑场次地点、时间、内外景、标题、人物和时长。
- 新增、编辑、删除和排序内容块。
- 对白关联项目角色或填写临时人物名称。
- 自动保存与手动保存策略由前端 Spec 进一步确定，但离开页面前必须处理未保存修改。

### 4.3 局部生成与改写

- 重新生成单个场次。
- 对选中的一个或多个内容块执行局部改写。
- 局部生成只产生目标范围的候选内容，不修改其他场次或内容块。
- 局部候选内容经用户采用后才写入正式剧本。
- 支持自定义改写指令。
- 提供预设方向：更爽、更虐、更悬疑、更口语化、更短视频化、压缩时长、增强结尾悬念。

### 4.4 检查与确认

- 检查结构完整性。
- 检查世界观规则。
- 检查人物身份、出场合理性和角色口吻。
- 检查当前分集剧情目标和结尾悬念。
- 检查单场及整集预计时长。
- 一般一致性问题以警告展示，不阻止保存。
- 缺少必填场次字段、内容块为空等结构错误阻止进入“已确认”。

## 5. 数据对象

### 5.1 EpisodeScript

表示某一集当前正式结构化剧本。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 剧本 ID |
| project_id | string | 是 | 项目 ID |
| episode_no | integer | 是 | 集数，必须在项目集数范围内 |
| title | string | 否 | 剧本标题，默认沿用分集标题 |
| version | integer | 是 | 正式剧本递增版本号 |
| source_content_version | string | 是 | 来源单集故事正文版本 |
| auto_duration_seconds | number | 是 | 系统自动估算总时长 |
| manual_duration_seconds | number | 否 | 用户人工覆盖总时长 |
| effective_duration_seconds | number | 是 | 实际使用时长；优先人工值，否则使用自动值 |
| status | artifact status | 是 | draft / pending_review / confirmed / needs_review |
| confirmed_at | datetime | 否 | 最近确认时间 |
| created_at | datetime | 是 | 创建时间 |
| updated_at | datetime | 是 | 更新时间 |

单项目同一集只有一个当前正式剧本聚合，但可以存在多个历史正式版本和候选生成记录。

### 5.2 ScriptScene

表示剧本中的一个有序场次。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 场次 ID |
| script_id | string | 是 | 所属正式剧本 |
| scene_no | integer | 是 | 展示编号，由排序结果自动生成 |
| title | string | 否 | 场次标题，可由系统生成或留空 |
| location | string | 是 | 场景地点 |
| time_of_day | string | 是 | 早晨 / 白天 / 黄昏 / 夜晚 / 其他 |
| interior_exterior | string | 是 | 内景 / 外景 / 混合 |
| character_refs | array | 否 | 项目角色快照引用列表，允许空场景 |
| auto_duration_seconds | number | 是 | 场次自动估算时长 |
| manual_duration_seconds | number | 否 | 场次人工覆盖时长 |
| effective_duration_seconds | number | 是 | 场次实际使用时长 |
| story_purpose | string | 否 | 剧情作用，默认折叠展示 |
| sort_order | integer | 是 | 稳定排序字段 |
| created_at | datetime | 是 | 创建时间 |
| updated_at | datetime | 是 | 更新时间 |

场次必须包含地点、时间、内外景和至少一个非空内容块。场次允许没有出场人物。

### 5.3 ScriptBlock

表示场次中的一个有序剧本内容块。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 内容块 ID |
| scene_id | string | 是 | 所属场次 |
| block_type | enum | 是 | action / dialogue / voiceover / transition |
| character_snapshot_id | string | 条件必填 | 对白关联的项目角色 |
| temporary_speaker_name | string | 条件必填 | 对白未关联项目角色时的临时人物名称 |
| content | string | 是 | 内容正文，去除首尾空白后不能为空 |
| emotion | string | 否 | 情绪提示，主要用于对白和旁白 |
| performance_note | string | 否 | 表演、语气、停顿或动作提示 |
| sort_order | integer | 是 | 场次内稳定排序字段 |
| created_at | datetime | 是 | 创建时间 |
| updated_at | datetime | 是 | 更新时间 |

对白块必须满足以下条件之一：

- 关联一个项目角色快照。
- 填写非空临时人物名称。

非对白内容块不要求人物字段。

### 5.4 ScriptGeneration

表示整集生成、场次重新生成或局部改写产生的候选版本。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 生成记录 ID |
| project_id | string | 是 | 项目 ID |
| episode_no | integer | 是 | 集数 |
| generation_scope | enum | 是 | episode / scene / blocks |
| target_scene_id | string | 条件必填 | 场次级生成目标 |
| target_block_ids | array | 条件必填 | 内容块级改写目标 |
| rewrite_preset | string | 否 | 预设改写方向 |
| instruction | string | 否 | 用户自定义指令 |
| input_snapshot | object | 是 | 生成时完整输入快照 |
| output_snapshot | object | 是 | 结构化候选输出 |
| status | enum | 是 | candidate / adopted / discarded |
| client_request_id | string | 是 | 幂等请求标识 |
| model_config_id | string | 否 | 模型配置 |
| model_name | string | 否 | 实际模型名称 |
| elapsed_ms | integer | 否 | 生成耗时 |
| adopted_at | datetime | 否 | 采用时间 |
| created_at | datetime | 是 | 创建时间 |

## 6. 时长规则

- 系统根据对白、旁白和动作内容自动估算场次时长。
- 估算系数由后端统一配置，不写死在页面中，便于后续按真实制作数据校准。
- 用户可以对场次时长和整集总时长进行人工覆盖。
- `effective_duration_seconds` 优先使用人工值，否则使用自动估算值。
- 页面同时展示自动估算值、人工值和最终生效值。
- 页面展示最终生效总时长与项目目标单集时长的偏差。
- 时长偏差默认是警告，不阻止保存或确认；具体严重阈值在后端 Spec 中定义。

## 7. 状态与下游门槛

### 7.1 剧本状态

- `draft`：正在编辑。
- `pending_review`：内容基本完成，等待人工确认。
- `confirmed`：已确认，可作为正式制作输入。
- `needs_review`：上游故事或资产发生变化，需要复核。

### 7.2 分镜门槛

- 草稿剧本可以生成草稿分镜。
- 草稿剧本生成的分镜必须记录来源剧本版本，并保持草稿状态。
- 只有来源于已确认剧本的分镜，才可以进入正式制作包。
- 剧本确认后不会自动确认已有草稿分镜，用户仍需检查来源和内容。

### 7.3 状态传播

- 单集故事正文、当前分集大纲、项目世界观或角色变化后，正式剧本标记为 `needs_review`。
- 采用整集候选、采用场次候选、采用内容块改写或保存实质内容变化后，下游分镜、后期准备和制作包标记为 `needs_review`。
- 仅修改不影响内容的展示字段时是否传播，由后端 Spec 按字段影响范围定义。

## 8. 候选版本与保留规则

- 正式采用版本永久保留。
- 未采用候选稿按单集最多保留最近 20 个。
- 超出上限后自动清理最旧的未采用候选稿。
- 已采用候选稿不能被自动清理。
- 用户可以主动放弃未采用候选稿。
- 采用新候选时，当前正式版本进入历史版本，但不得被删除。

## 9. 一致性检查

检查项包括：

- 世界观规则冲突。
- 人物身份、关系、目标和秘密冲突。
- 人物口吻明显偏离角色卡。
- 使用不存在或未加载的角色。
- 场次与分集剧情目标不一致。
- 开场钩子、关键冲突、反转或结尾悬念缺失。
- 场次结构不完整。
- 对白缺少说话人。
- 空内容块。
- 时长明显偏离项目目标。

检查结果等级：

- `error`：结构错误，阻止确认。
- `warning`：一致性或质量风险，不阻止保存和确认。
- `info`：优化建议。

## 10. 交互要求

### 10.1 页面结构

- 顶部展示集数、剧本状态、目标时长、当前时长和主要操作。
- 主区域按场次展示，支持折叠、展开和排序。
- 场次标题、地点、时间、内外景、人物和时长直接展示。
- 剧情作用和一致性提示默认折叠。
- 内容块以真实顺序展示，不按类型拆成多个大文本框。
- 右侧上下文继续只读展示分集大纲、正文摘要、角色和世界观。
- 右侧提供当前集完整故事正文的只读快速参考，具体规则见[剧本来源正文快速参考](./script-source-reference.md)。

### 10.2 空状态

- 没有正式剧本时，引导用户从当前单集故事正文生成候选剧本。
- 缺少单集故事正文时，生成按钮禁用，并提供返回故事文本模块的入口。
- 上游资产不完整时允许人工创建草稿，但生成前明确提示连续性风险。

### 10.3 生成与采用

- 整集生成、单场重写和局部改写都展示生成中状态并防止重复提交。
- 生成失败时保留当前正式内容。
- 候选结果允许预览、采用和放弃。
- 采用操作明确提示会影响的下游内容。

### 10.4 编辑保护

- 删除场次前提示关联分镜将需要检查。
- 场次或内容块排序后重新计算展示编号。
- 页面离开、切换集数或采用候选前必须处理未保存修改。
- 批量操作失败时要明确哪些项目成功、哪些失败。

## 11. 旧数据迁移

现有四字段剧本迁移规则：

1. 为原剧本创建一个标题为“待整理场次”的场次。
2. 原动作说明转换为动作块。
3. 原对白转换为对白块；无法识别说话人时使用待整理临时人物名称或保留为待处理内容。
4. 原旁白转换为旁白块。
5. 原场景说明用于初始化场次地点或附加为动作块，具体解析失败时保留原文。
6. 由于原数据无法还原真实顺序，迁移后的剧本统一标记为 `needs_review`。
7. 迁移不得丢失任何非空原始文本，并保留迁移来源快照。

## 12. 用户故事

1. 作为短剧创作者，我想从单集故事正文生成结构化剧本，以便进入视频制作。
2. 作为短剧创作者，我想按场次查看剧本，以便快速理解拍摄结构。
3. 作为短剧创作者，我想让动作、对白、旁白和转场保持真实顺序，以便准确拆分镜头。
4. 作为短剧创作者，我想让对白关联项目角色，以便保持角色口吻和后续配音一致。
5. 作为短剧创作者，我想使用临时人物名称，以便处理尚未沉淀为角色卡的路人角色。
6. 作为短剧创作者，我想编辑单个场次而不影响其他场次，以便减少返工。
7. 作为短剧创作者，我想重新生成不满意的场次，以便保留其他人工调整。
8. 作为短剧创作者，我想对选中内容进行定向改写，以便精确控制修改范围。
9. 作为短剧创作者，我想使用常用改写方向，以便快速调整爽感、悬疑和节奏。
10. 作为短剧创作者，我想预览候选版本后再采用，以便避免覆盖满意内容。
11. 作为短剧创作者，我想查看场次及整集时长，以便控制单集节奏。
12. 作为短剧创作者，我想人工修正时长，以便纳入表演和镜头节奏判断。
13. 作为短剧创作者，我想检查人物和世界观一致性，以便减少后续制作返工。
14. 作为短剧创作者，我想用草稿剧本提前生成草稿分镜，以便快速探索视觉方案。
15. 作为短剧创作者，我想确认正式剧本版本，以便为制作包提供稳定输入。
16. 作为旧项目用户，我想完整迁移原剧本文本，以便继续使用已有内容。

## 13. 验收标准

- 系统可以基于当前单集故事正文生成结构化候选剧本。
- 候选剧本采用前不修改正式剧本。
- 正式剧本由一个或多个有序场次组成。
- 每个场次包含地点、时间、内外景和至少一个非空内容块。
- 内容块类型仅允许动作、对白、旁白和转场。
- 对白块必须关联项目角色或填写临时人物名称。
- 用户可以新增、编辑、删除和排序场次及内容块。
- 用户可以重新生成单场或改写选中内容，且不影响范围外内容。
- 页面展示自动、人工和最终生效时长及目标偏差。
- 一致性警告不阻止保存；结构错误阻止确认。
- 草稿剧本可以生成草稿分镜，但不能直接进入正式制作包。
- 正式采用版本永久保留，未采用候选每集最多保留 20 个。
- 上游或剧本变化后正确传播下游状态。
- 旧四字段剧本迁移后不丢失文本并标记为需要检查。

## 14. 实现决策

- 以 `EpisodeScript` 作为聚合根，场次和内容块只能通过剧本聚合进行有序修改。
- 生成服务只负责产生结构化候选结果，采用服务负责原子替换目标范围并记录正式版本。
- 时长估算封装为独立服务，输入结构化剧本，输出场次和整集估算值，便于单独校准和测试。
- 一致性检查封装为独立服务，返回结构化问题列表，不直接修改内容。
- 版本保留和清理封装为独立策略，不能删除正式采用版本。
- 旧数据迁移封装为可重复执行且幂等的迁移过程。
- 数据写入必须保持场次和内容块排序一致，避免客户端自行拼接不完整聚合。

## 15. 测试决策

测试只验证外部行为和业务合同，不绑定具体 UI 组件或内部函数。

必须覆盖：

- 整集候选生成、采用、放弃和幂等请求。
- 场次及内容块新增、编辑、删除和排序。
- 对白角色引用与临时人物校验。
- 单场重新生成和内容块局部改写的影响范围。
- 自动时长、人工覆盖及最终时长计算。
- 结构错误、一致性警告和确认门槛。
- 草稿剧本到草稿分镜及正式制作包门槛。
- 上游和剧本变化后的状态传播。
- 候选版本 20 条上限及正式版本保护。
- 旧四字段剧本迁移完整性和幂等性。
- 空正文、缺少上游、生成失败、并发采用和并发排序。

## 16. 非目标

- 不在本模块生成或编辑分镜。
- 不生成图片、视频或音频素材。
- 不维护字幕时间轴。
- 不直接适配 Seedance 或剪映格式。
- 不在第一版提供多人实时协同编辑。
- 不根据 AI 建议自动修改正式剧本。
