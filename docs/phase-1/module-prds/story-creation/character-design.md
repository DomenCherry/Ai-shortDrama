# 模块 PRD：人物设定生成

> 状态：**未实现** — 本文档为占位规格，待 AI 生成能力接入后补充详细设计。

## 1. 功能定位

系统根据选题策划、整体故事大纲和项目内已加载的角色卡快照，生成人物设定，包括主角、反派和重要配角的背景、性格、目标、秘密、关系和视觉描述。

## 2. 输出内容

人物设定应包含：

- 主角设定。
- 反派设定。
- 重要配角设定。
- 人物背景。
- 人物性格。
- 人物目标。
- 人物秘密。
- 人物关系。
- 人物情感弧线。
- 人物在剧情中的功能。
- 人物视觉描述。
- 形象关键词。

默认建议：

- 第一期至少生成 1 名主角、1 名主要反派、2 到 4 名配角。
- 人物关系先用文本列表表达，不做可视化关系图。
- 主要人物都应包含可用于生成示意图的视觉描述和形象关键词。

## 3. 交互要求

- 用户可以编辑人物信息。
- 用户可以新增、删除人物。
- 用户可以重新生成全部人物设定。
- 用户可以单独改写某个人物。
- 用户确认人物文字设定后，可以为该人物生成示意图。

## 4. 数据对象

### 4.1 Character

表示人物设定。

字段建议：

- project_id
- name
- role_type
- background
- personality
- goal
- secret
- relationship_notes
- emotional_arc
- story_function
- visual_description
- image_keywords
- image_status

## 5. 用户故事

17. 作为个人短剧创作者，我想生成人物设定，以便快速搭建角色体系。
18. 作为个人短剧创作者，我想生成主角的背景、目标和秘密，以便主角有更强故事驱动力。
19. 作为个人短剧创作者，我想生成反派设定，以便剧情冲突更明确。
20. 作为个人短剧创作者，我想生成配角设定，以便支撑多集剧情发展。
21. 作为个人短剧创作者，我想编辑人物设定，以便让角色更符合我的想法。
22. 作为个人短剧创作者，我想单独改写某个人物，以便优化角色而不影响全部内容。

## 6. 验收标准

- 系统可以生成完整人物设定。
- 如果项目已加载角色卡，人物设定应优先保留项目内角色卡快照中的核心身份、目标、关系和视觉描述。
- 人物设定可被后续人物示意图、分集大纲和剧本引用。
- 用户修改人物后，后续生成内容应尽量遵循最新人物设定。
