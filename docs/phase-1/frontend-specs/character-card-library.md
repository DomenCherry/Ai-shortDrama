# 前端页面 Spec：角色卡库

## 1. 页面信息

- 页面组名称：角色卡库
- 所属阶段：第一期
- 目标用户：个人短剧创作者
- 关联模块 PRD：[角色卡库](../module-prds/character-card-library.md)
- 页面路径：
  - 角色卡列表页：`/character-cards`
  - 新建角色卡页：`/character-cards/new`
  - 角色卡详情编辑页：`/character-cards/[id]`

## 2. 页面目标

角色卡库用于让用户独立创建、查看、编辑和管理可复用人物资产。角色卡只保存跨项目稳定的人物基础、人设原型、核心欲望、口吻和视觉素材；具体剧情目标、人物关系、冲突、反转、情感弧线和剧情功能在项目或世界观阶段塑造。

为保证页面结构清晰，第一期不采用“列表 + 新建表单”混合在同一页面的方式。角色列表和新建角色卡必须拆成独立页面：

- 列表页专注于浏览、搜索、筛选、归档和进入详情。
- 新建页专注于低干扰地完成角色卡创建。
- 详情编辑页专注于维护已有角色卡、状态管理和加载到项目。

用户离开页面组时，应完成以下结果之一：

- 搜索或筛选已有角色卡。
- 创建并保存一个角色卡。
- 编辑已有角色卡。
- 上传或替换角色参考图。
- 基于角色设定、视觉提示词和参考图生成人物三视图。
- 将角色卡归档。
- 预览角色卡并准备加载到项目。

## 3. 用户流程

### 3.1 查看和筛选角色卡

```text
进入角色卡库列表页
 -> 查看角色卡列表
 -> 输入角色名关键词或选择筛选条件
 -> 查看筛选后的角色卡
 -> 点击角色卡
 -> 进入角色卡详情编辑页
```

### 3.2 创建角色卡

```text
进入角色卡库列表页
 -> 点击新建角色卡
 -> 跳转到 /character-cards/new
 -> 填写基础身份
 -> 选择角色性别
 -> 选择人物原型
 -> 填写核心欲望 / 人物执念
 -> 填写口吻风格
 -> 填写视觉描述、形象关键词和人物三视图提示词
 -> 点击生成提示词
 -> 系统根据当前字段拼接三视图提示词
 -> 用户手动调整提示词
 -> 可选上传参考图
 -> 保存角色卡
 -> 保存成功后跳转到 /character-cards/[id]
```

### 3.3 编辑角色卡

```text
进入角色卡详情编辑页
 -> 修改角色设定
 -> 页面显示未保存状态
 -> 上传或替换参考图
 -> 点击生成人物三视图
 -> 点击保存
 -> 保存成功后更新版本和更新时间
```

### 3.4 归档角色卡

```text
进入角色卡列表页或详情编辑页
 -> 点击归档
 -> 系统展示确认提示
 -> 用户确认
 -> 角色卡状态变为 archived
 -> 角色不再出现在新项目加载候选中
```

## 4. 信息架构

### 4.1 角色卡列表页

列表页只展示角色卡集合和列表级操作，不展示完整创建表单。

信息分组：

- 页面标题区：角色卡库、简短说明、新建角色卡按钮。
- 筛选区：角色名搜索、性别筛选、人物原型筛选、状态筛选。
- 列表区：展示角色卡卡片或表格。
- 状态反馈区：列表加载中、列表加载失败、空数据。
- 快捷操作区：进入详情、归档、加载到项目入口。

列表条目展示：

- 角色名。
- 性别。
- 人物原型。
- 身份摘要。
- 核心欲望 / 人物执念。
- 视觉关键词。
- 是否存在参考图。
- 状态。
- 版本。
- 更新时间。

### 4.2 新建角色卡页

新建页用于创建一个全新的角色卡。页面不展示角色卡列表，避免用户在填写时被列表信息干扰。

信息分组：

- 页面标题区：新建角色卡、返回列表入口。
- 基础身份区。
- 人物资产设定区。
- 口吻与对白风格区。
- 视觉设定区。
- 参考图上传区。
- 人物三视图生成区。
- 三视图提示词编辑区。
- 操作区：取消、保存。

新建页保存成功后，应跳转到该角色卡的详情编辑页，而不是停留在空白新建页。

### 4.3 角色卡详情编辑页

详情编辑页用于查看和维护一个已保存角色卡。

信息分组：

- 页面标题区：角色名、状态、版本、返回列表入口。
- 基础身份区。
- 人物资产设定区。
- 口吻与对白风格区。
- 视觉设定区。
- 参考图上传区。
- 人物三视图生成区。
- 项目加载区。
- 危险操作区：归档角色卡。
- 状态反馈区：保存中、保存成功、保存失败、未保存变更。

## 5. 布局结构

### 5.1 列表页布局

- 使用 `.page-header` 展示页面标题、说明和“新建角色卡”主按钮。
- 筛选区使用横向紧凑布局，优先保证桌面端扫描效率。
- 列表区使用卡片列表或表格，不与编辑表单并排。
- 空状态需要提供明确的新建入口。
- 角色卡条目中的长文本应截断或换行，不允许撑破容器。

### 5.2 新建页布局

- 使用单列或主内容 + 辅助说明的布局，主表单宽度需要受控。
- 表单按业务含义分组，不使用过大的营销式标题。
- 主操作按钮放在表单末尾，包含“取消”和“保存”。
- 保存按钮在必填字段缺失时禁用或点击后展示字段级错误。
- 页面标题区的“返回列表”按钮必须可点击；点击后返回 `/character-cards`。
- 如果已有未保存内容，点击“返回列表”或“取消”时先展示离开确认；确认后必须返回列表页。
- 新建页不展示完整角色卡列表。

### 5.3 详情编辑页布局

- 使用单列表单或“主表单 + 侧栏状态信息”的布局。
- 侧栏可以展示状态、版本、更新时间、项目加载操作和参考图预览。
- 视觉设定区下方展示参考图上传和三视图生成结果，便于用户确认角色形象。
- 新建页的人物三视图区需要把“生成提示词”和“生成人物三视图”区分为两个动作：前者只生成可编辑文本，后者才保存草稿并调用图片生成接口。
- 操作区应区分主操作和危险操作，归档按钮不能与保存按钮视觉层级相同。
- archived 状态应明确提示当前角色已归档，不可作为新项目加载候选。

## 6. 字段与控件

### 6.1 列表页控件

| 字段/控件 | 类型 | 是否必填 | 默认值 | 校验/约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 角色名搜索 | 文本输入 | 否 | 空 | 最多 100 字 | 按角色名和身份摘要搜索 |
| 性别筛选 | 下拉选择 | 否 | 全部 | 全部、男、女 | 按角色性别筛选角色卡 |
| 人物原型筛选 | 下拉选择 | 否 | 全部 | 选项来自固定枚举或后端返回 | 例如复仇者、守护者、操控者、成长型、权力型、治愈型 |
| 状态筛选 | 下拉选择 | 否 | 全部 | draft、active、archived | 控制列表展示范围 |
| 新建角色卡 | 按钮 | 否 | 无 | 点击后跳转 `/character-cards/new` | 主操作 |
| 角色卡条目 | 卡片或表格行 | 否 | 无 | 点击后跳转 `/character-cards/[id]` | 展示角色名、性别、人物原型、核心欲望、视觉关键词、状态、版本、更新时间 |
| 快捷归档 | 按钮 | 否 | 无 | 已保存角色卡可点击 | 需要二次确认 |

### 6.2 基础身份

| 字段/控件 | 类型 | 是否必填 | 默认值 | 校验/约束 | 填写引导/示例 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 角色名 | 文本输入 | 是 | 空 | 1 到 80 字 | 示例：沈砚、林晚、顾知衡 | 角色卡主标识 |
| 性别 | 下拉选择或分段控件 | 是 | 空 | 只能选择男或女，保存时不能为空 | 选择角色性别：男 / 女 | 用于故事上下文、人物设定、视觉生成和对白称谓约束 |
| 人物原型 | 下拉选择 | 是 | 成长型 | 复仇者、守护者、操控者、成长型、权力型、治愈型、探索者、其他 | 选择跨项目稳定的人设原型 | 不表示主角、反派、配角等具体项目职能 |
| 身份摘要 | 文本输入或短文本域 | 是 | 空 | 1 到 200 字 | 示例：隐忍复仇型豪门继承人；表面温顺、暗中布局的女主 | 用一句话说明角色最核心的身份和戏剧张力 |
| 状态 | 分段控件或下拉 | 是 | draft | draft、active、archived | 草稿用于未完成角色；可加载用于可加入项目的角色 | 只有 active 可以加载到项目 |

### 6.3 人物资产设定

| 字段/控件 | 类型 | 是否必填 | 默认值 | 校验/约束 | 填写引导/示例 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 人物背景 | 多行文本 | 否 | 空 | 建议不超过 2000 字 | 写清跨项目稳定的出身、经历、当前处境。示例：幼年被家族边缘化，成年后以投资人身份回归。 | 描述稳定经历和处境，不写具体项目集数剧情 |
| 性格 | 多行文本 | 否 | 空 | 建议不超过 1000 字 | 示例：外冷内热、极强控制欲、习惯先观察再行动。 | 描述稳定性格特征 |
| 核心欲望 / 人物执念 | 多行文本 | 是 | 空 | 1 到 1000 字 | 示例：证明自身价值、掌控命运、守护亲人、摆脱被安排的人生。 | 描述跨项目稳定的内在驱动力，不写某个项目的具体主线目标 |

以下旧版字段不在新建页和详情页展示：深层动机、人物秘密、冲突点、人物关系说明、情感弧线、剧情功能。它们保留在数据结构中仅用于历史兼容，保存旧角色卡时不得因为字段隐藏而清空旧数据。

### 6.4 口吻与视觉设定

| 字段/控件 | 类型 | 是否必填 | 默认值 | 校验/约束 | 填写引导/示例 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 说话方式 | 多行文本 | 否 | 空 | 建议不超过 1000 字 | 示例：语速慢、很少解释、常用反问压迫对方。 | 后续剧本对白参考 |
| 常用表达 | 多行文本 | 否 | 空 | 建议每行一条 | 示例：你确定要知道真相吗？；这笔账，我记了很多年。 | 用于沉淀口头禅或习惯表达 |
| 视觉描述 | 多行文本 | 否 | 空 | 建议不超过 1500 字 | 示例：28 岁左右，冷静克制，黑色长发，浅色西装，眼神疏离但有攻击性。 | 用于人物示意图、三视图和视频一致性参考 |
| 形象关键词 | 标签输入或文本输入 | 否 | 空 | 建议 3 到 12 个关键词 | 示例：冷感、精英感、黑长直、浅色西装、克制、危险感。 | 用于快速约束视觉方向 |
| 三视图提示词 | 多行文本 | 否 | 空，可由“生成提示词”按钮填充 | 建议包含年龄、体型、发型、服装、气质、色彩、风格，不直接模仿现实人物 | 示例：全身角色设计，正面、侧面、背面，统一服装，干净背景，短剧人物设定图。 | 用户可手动编辑；调用图片模型生成三视图时使用 |
| 生成提示词 | 按钮 | 否 | 无 | 至少填写角色名、性别和身份摘要；建议填写视觉描述或形象关键词 | 点击后按当前字段拼接三视图提示词；如果提示词已被用户修改，覆盖前需要确认。 | 只更新三视图提示词文本，不保存角色卡，不调用图片生成接口 |
| 参考图上传 | 文件上传 | 否 | 无 | 支持 png、jpg、webp；单张建议不超过 10MB；可替换 | 上传已确认的人物氛围图、服装参考或脸部风格参考。 | 替代手动填写本地路径，作为三视图生成参考 |
| 参考图预览 | 图片预览 | 否 | 无 | 上传成功后展示缩略图 | 上传失败或格式不支持时显示稳定占位状态。 | 用于确认参考图是否正确 |
| 三视图生成结果 | 图片预览组 | 否 | 无 | 至少展示正面、侧面、背面；生成失败保留原图 | 用户确认后保存为角色视觉参考素材。 | 用于后续视频生成的人物一致性参考 |

| 生成提示词 | 新建页 | 按钮 | 至少填写角色名、性别和身份摘要；建议填写视觉描述或形象关键词 | 根据当前表单字段拼接三视图提示词，写入可编辑文本域 |

## 7. 交互与状态

### 7.1 列表页状态

- 初始状态：加载角色卡列表。
- 空数据状态：列表为空时展示新建角色卡入口。
- 搜索筛选：搜索词、性别、人物原型或状态筛选条件变化后刷新列表。
- 列表加载失败：展示中文错误，并提供重试入口。
- 归档确认：归档前弹出确认，不允许静默归档。
- 点击角色卡：跳转到详情编辑页，不在列表页内展开完整表单。

### 7.2 新建页状态

- 初始状态：展示空白表单，状态默认为 draft。
- 性别初始为空，保存前必须选择男或女。
- 字段引导：每个字段都必须展示简短说明、placeholder 或示例文案，帮助用户理解应该填写什么。
- 编辑中：字段变更后展示“未保存”状态。
- 必填缺失：保存前在字段附近展示错误。
- 返回列表：点击页面标题区“返回列表”按钮时，如果无未保存内容，直接跳转 `/character-cards`；如果有未保存内容，确认后跳转。
- 取消创建：点击“取消”时与返回列表一致，不能无响应。
- 参考图上传中：点击上传参考图后，系统先自动保存角色卡草稿，再上传参考图；上传期间上传按钮禁用并展示上传中。
- 参考图上传成功：页面跳转到角色详情页，并在详情页展示参考图缩略图和上传成功提示。
- 参考图上传失败：如果草稿尚未创建，停留新建页并保留当前表单内容；如果草稿已创建，跳转详情页并提示用户重试。
- 生成提示词：点击“生成提示词”后，系统按当前表单内容生成三视图提示词并写入三视图提示词文本域；该动作不保存草稿、不上传参考图、不调用图片生成 API。
- 提示词手动调整：用户可以继续编辑三视图提示词，后续生成人物三视图时使用用户最终编辑后的文本。
- 提示词覆盖确认：如果三视图提示词已有内容且用户曾手动修改，再次点击“生成提示词”时需要确认后才能覆盖。
- 三视图生成中：点击生成人物三视图后，系统先自动保存角色卡草稿，再调用图片生成 API；生成按钮禁用并展示生成中，避免重复提交。
- 三视图生成成功：页面跳转到角色详情页，展示正面、侧面、背面预览，并提供确认当前三视图的操作。
- 三视图生成失败：如果角色卡草稿已保存，页面跳转详情页并提示可重试；如果草稿保存失败，停留新建页并保留用户已填写内容。
- 保存中：保存按钮禁用，显示保存中。
- 保存成功：跳转到 `/character-cards/[id]`，并在详情页展示成功提示。
- 保存失败：展示中文错误，保留用户已输入内容。
- 离开确认：存在未保存输入时，点击取消或返回列表需要确认。

### 7.3 详情编辑页状态

- 详情加载中：展示详情页加载状态。
- 详情加载失败：展示中文错误，并提供返回列表入口。
- 编辑中：字段变更后展示“有未保存修改”。
- 保存中：保存按钮禁用，显示保存中。
- 保存成功：展示成功提示，更新版本和更新时间。
- 保存失败：展示中文错误，保留用户已输入内容。
- 状态切换：从 draft 切换 active 时先校验必填字段。
- archived 状态：详情可查看；第一版不建议继续编辑已归档角色。
- 参考图预览失败：显示“参考图无法预览，请检查地址或路径”。
- 参考图上传中：上传按钮禁用并展示上传中，上传成功后更新角色参考图预览。
- 三视图生成中：生成按钮禁用并展示生成中，生成任务完成前不允许重复提交。
- 三视图生成成功：展示三视图预览，用户确认后保存为角色视觉参考素材。
- 三视图生成失败：展示中文错误，保留上一版已确认三视图。
- 加载到项目：非 active 状态按钮禁用，并提示“只有可加载角色卡可以加入项目”。
- 加载到项目：同一角色卡已加载到目标项目时，作为新角色加载按钮禁用，并提示“该角色卡已加载到项目，不能重复加载”。
- 未保存保护：当前角色卡有未保存修改时，不允许加载到项目。

### 7.4 三视图生成规则

- “生成提示词”和“生成人物三视图”是两个独立动作；生成提示词只在前端拼接文本，生成人物三视图才调用后端图片生成接口。
- 三视图提示词自动拼接顺序为：固定三视图规范、角色名、性别、身份摘要、视觉描述、形象关键词、人物原型、性格、核心欲望 / 人物执念、用户已填写的三视图补充内容、参考图说明。
- 固定三视图规范必须包含：同一角色、正面、侧面、背面、全身、统一服装、干净背景、适合作为短剧人物视觉参考、不模仿任何特定现实人物。
- 视觉描述和形象关键词是三视图提示词的核心字段；人物原型、性格和核心欲望 / 人物执念只作为气质补充，不应压过外观描述。
- 如果用户已上传或选择参考图，自动提示词可加入“参考图用于服装、脸部风格或氛围参考”的说明，但不得展示本地文件系统路径。
- 三视图生成必须合并当前角色卡中的可复用人物资产信息，包括角色名、性别、人物原型、身份摘要、人物背景、性格、核心欲望 / 人物执念、说话方式、常用表达、视觉描述、形象关键词和三视图提示词。
- 三视图生成不得使用旧版剧情字段：深层动机、人物秘密、冲突点、人物关系说明、情感弧线、剧情功能。
- 如果用户上传了参考图，后端应读取角色卡中已保存的参考图，并在图片模型支持时作为参考图输入；模型不支持时应提示用户更换模型或关闭参考图能力。
- 生成结果应包含同一角色的正面、侧面、背面，不允许生成三个风格明显不一致的人物。
- 生成结果在用户确认前只作为候选图，不应覆盖已确认视觉参考。
- 用户确认三视图后，系统保存三视图图片地址/本地路径、生成提示词、参考图来源、生成版本和确认状态。
- 如果图片 API 未配置或测试不可用，按钮禁用，并提示“请先在模型设置中配置可用的图片生成 API”。

## 8. API 依赖

接口合同、字段校验、旧字段兼容、参考图上传、三视图生成和模型前置校验以后端接口 Spec 为准：[角色卡库后端 Spec](../backend-specs/character-card-library.md)。本节只描述页面依赖关系。

| 行为 | 前端方法 | 后端接口 | 请求数据 | 响应数据 | 错误处理 |
| --- | --- | --- | --- | --- | --- |
| 获取角色卡列表 | `listCharacterCards` | `GET /api/character-cards` | 搜索词、性别、人物原型、状态 | 角色卡摘要列表 | 展示“角色卡列表加载失败” |
| 创建角色卡 | `createCharacterCard` | `POST /api/character-cards` | 角色卡表单字段，必须包含 `gender`；内部 `goal` 表示核心欲望 / 人物执念 | 新角色卡详情 | 展示字段错误或“角色卡创建失败” |
| 获取角色卡详情 | `getCharacterCard` | `GET /api/character-cards/{id}` | 角色卡 ID | 角色卡详情 | 展示“角色卡详情加载失败” |
| 更新角色卡 | `updateCharacterCard` | `PUT /api/character-cards/{id}` | 角色卡表单字段，必须包含 `gender`；隐藏旧版剧情字段不得被清空 | 更新后的角色卡详情 | 展示字段错误或“角色卡保存失败” |
| 归档角色卡 | `archiveCharacterCard` | `POST /api/character-cards/{id}/archive` | 角色卡 ID | 更新后的角色卡详情 | 展示“角色卡归档失败” |
| 加载到项目 | `loadCharacterCardToProject` | `POST /api/projects/{project_id}/character-snapshots` | 角色卡 ID、加载方式、可选替换目标；同一角色卡已加载时不能作为新角色重复加载 | 项目内角色快照 | 展示已加载、冲突提示或“角色卡加载失败” |
| 上传角色参考图 | `uploadCharacterReferenceImage` | `POST /api/character-cards/{id}/reference-images` | JSON：文件名、content type、base64 data URL | 图片地址/本地路径、预览地址 | 展示“参考图上传失败” |
| 生成人物三视图 | `generateCharacterTurnaround` | `POST /api/character-cards/{id}/turnaround-images` | 人物资产字段、三视图提示词、参考图上下文 | 三视图生成结果、生成版本、提示词快照 | 展示“三视图生成失败” |
| 确认人物三视图 | `confirmCharacterTurnaround` | `POST /api/character-cards/{id}/turnaround-images/{image_id}/confirm` | 三视图结果 ID | 已确认视觉参考信息 | 展示“三视图确认失败” |

后端接口实现时应与后端接口 Spec 和后端 schema 保持一致。

新建页如果角色卡尚未保存，第一期采用自动保存草稿策略：

- 用户点击上传参考图或生成人物三视图时，系统先校验并创建角色卡草稿。
- 草稿创建成功后，再调用参考图上传或三视图生成接口。
- 上传或生成成功后跳转详情页展示结果。
- 草稿创建成功但上传或生成失败时，跳转详情页并提示用户重试，避免重复创建角色卡。
- 第一版不使用临时素材接口，避免临时素材回收和孤儿文件管理复杂化。

## 9. 错误提示

- 角色名不能为空。
- 性别不能为空。
- 人物原型不能为空。
- 身份摘要不能为空。
- 核心欲望 / 人物执念不能为空。
- 只有可加载状态的角色卡可以加载到项目。
- 该角色卡已加载到项目，不能重复加载。
- 角色名已存在，请确认是否继续创建或修改名称。
- 当前角色卡有未保存修改，请先保存后再加载到项目。
- 当前页面有未保存内容，确认离开吗？
- 请先保存角色卡草稿，再上传参考图。
- 请上传 png、jpg 或 webp 格式图片。
- 参考图不能超过 10MB。
- 参考图上传失败，请稍后重试。
- 请先填写角色名、性别和身份摘要后再生成提示词。
- 当前三视图提示词已有手动修改，确认覆盖吗？
- 请先填写角色名、性别、身份摘要、核心欲望 / 人物执念，以及视觉描述或形象关键词后再生成三视图。
- 请先在模型设置中配置可用的图片生成 API。
- 三视图生成失败，请稍后重试。
- 三视图确认失败，请稍后重试。
- 角色卡创建失败，请稍后重试。
- 角色卡保存失败，请稍后重试。
- 角色卡归档失败，请稍后重试。
- 参考图无法预览，请检查地址或路径。
- 角色名与项目中已有角色重复，请选择作为新角色加载或替换已有角色。

错误信息不得展示 API Key、内部异常堆栈或数据库错误原文。

## 10. 桌面端布局要求

- 第一期角色卡库默认面向桌面端使用，不要求移动端专门适配。
- 列表页筛选控件使用横向紧凑布局，桌面端不应挤压主操作按钮。
- 新建页和详情页表单字段宽度占满容器。
- 字段说明、示例文案和错误提示不允许覆盖输入框。
- 多行文本字段高度应稳定，内容过长时使用滚动或合理扩展。
- 角色卡条目中的长文本应截断或换行，不能撑破卡片。
- 参考图预览保持固定比例，加载失败时展示稳定占位区域。
- 三视图预览在桌面端可以横向展示，单张图保持稳定比例。

## 11. 验收标准

- 用户可以进入角色卡列表页 `/character-cards`。
- 用户可以看到角色卡列表、搜索框、性别筛选、人物原型筛选和状态筛选。
- 点击“新建角色卡”后，用户进入 `/character-cards/new`。
- 新建页不展示角色卡列表。
- 新建页“返回列表”按钮点击后必须返回 `/character-cards`；存在未保存内容时必须先确认。
- 新建页每个字段都展示说明、示例或 placeholder，引导用户填写。
- 用户可以在新建页创建角色卡。
- 新建角色卡保存成功后，页面跳转到该角色卡详情编辑页。
- 点击列表中的角色卡后，用户进入 `/character-cards/[id]`。
- 详情编辑页不与列表页杂糅展示。
- 用户可以编辑角色基础身份、性别、人物原型、核心欲望 / 人物执念、口吻和视觉描述。
- 旧版剧情字段不在新建页和详情页展示，编辑旧角色卡时不得清空旧数据。
- 用户保存角色卡时必须选择性别，性别只支持男或女。
- 必填字段缺失时，系统阻止保存并显示中文提示。
- 用户保存成功后，页面展示成功状态并更新角色卡信息。
- 用户修改字段后，页面展示未保存状态。
- 用户可以归档角色卡，归档前必须确认。
- `archived` 角色卡不应作为加载到新项目的可选项。
- 只有 `active` 角色卡可以触发加载到项目。
- 同一角色卡不能重复加载到同一项目。
- 用户可以手动上传参考图，上传成功后展示预览；不再要求用户手动填写本地路径。
- 用户可以在新建页点击“生成提示词”，根据当前字段自动生成三视图提示词。
- 用户可以在生成人物三视图前手动调整系统生成的提示词。
- 用户手动修改提示词后，再次点击“生成提示词”需要确认后才能覆盖。
- 用户可以基于人物资产字段和参考图调用图片生成接口生成人物三视图。
- 三视图生成中、成功、失败、确认状态都有明确反馈。
- 用户确认三视图后，该三视图应作为角色视觉参考信息保存。
- 桌面端列表、新建和详情编辑均可正常操作。
- 页面风格遵守 [前端风格规范](../../technical/frontend-style-guide.md)。
- 实现代码中复杂状态、业务校验和快照加载规则需要符合 [编码规范](../../technical/coding-standards.md) 的注释要求。
- TypeScript 检查通过。

## 12. 非目标

- 不做角色一致性训练。
- 不做复杂人物关系图。
- 不做多角色对话模拟。
- 不做完整视频生成、场景图生成和分镜图生成。
- 不做多版本三视图差异对比。
- 不做角色卡版本差异对比。
- 不做自动同步角色卡新版本到已加载项目。
- 不做多人共享、权限和协作。
