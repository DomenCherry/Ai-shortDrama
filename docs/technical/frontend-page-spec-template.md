# 前端页面 Spec 模板

## 1. 页面信息

- 页面名称：
- 页面路径：
- 所属阶段：
- 关联 PRD：
- 关联功能设计：
- 目标用户：

## 2. 页面目标

说明该页面帮助用户完成什么任务，以及页面完成后的业务结果。

需要明确：

- 用户进入页面时通常已经具备什么上下文。
- 用户离开页面时应该完成什么。
- 该页面在整体流程中的上游和下游。

## 3. 用户流程

用步骤描述用户在页面内的主要操作路径。

示例：

```text
进入页面
 -> 查看当前状态
 -> 填写或编辑内容
 -> 触发保存、测试或生成
 -> 查看结果或错误
 -> 进入下一步
```

## 4. 信息架构

列出页面需要展示的信息分组。

建议包含：

- 页面标题和说明。
- 主要表单或内容区域。
- 状态反馈区域。
- 操作按钮区域。
- 辅助说明或约束提示。

## 5. 布局结构

说明页面布局，不写实现代码。

需要明确：

- 是否使用 `.page-header`。
- 主要内容是否使用 `.panel`。
- 是否使用 `.stack`、`.grid-2`。
- 主操作按钮位置。
- 窄屏下的布局变化。

表格格式：

|  |  |  |  |  |  |

## 7. 交互与状态

列出页面需要处理的交互状态。

至少考虑：

- 初始状态。
- 加载中。
- 保存中、测试中或生成中。
- 成功状态。
- 失败状态。
- 禁用状态。
- 空数据状态。
- 用户修改后未保存状态。

## 8. API 依赖

列出页面依赖的前端 API service 方法和后端接口。

表格格式：

| 行为 | 前端方法 | 后端接口 | 请求数据 | 响应数据 | 错误处理 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

如果页面不依赖 API，应明确写“无”。

## 9. 错误提示

列出用户可见错误信息。

要求：

- 使用中文。
- 能说明发生了什么。
- 必要时告诉用户如何修正。
- 不展示 API Key 等敏感信息。

## 10. 响应式要求

说明移动端或窄屏下的最低可用要求。

至少考虑：

- 是否允许横向溢出。
- 双列布局如何降级。
- 按钮组如何换行。
- 长文本如何展示。

## 11. 验收标准

列出实现完成后必须满足的检查点。

建议包含：

- 页面功能检查。
- 校验和错误提示检查。
- 样式一致性检查。
- 响应式检查。
- TypeScript 检查。
