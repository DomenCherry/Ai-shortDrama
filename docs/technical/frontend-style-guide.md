# 前端风格规范

## 1. 目标

本规范用于保证 AI 短剧制作工具的前端页面在后续迭代中保持一致。

当前产品定位是“短剧创作工作台”，界面应优先服务创作流程、表单配置、生成结果确认和内容编辑，不做营销页式视觉表达。

核心原则：

- 清晰：用户能快速理解当前页面要完成什么任务。
- 紧凑：页面以工作效率为主，减少装饰性空间。
- 稳定：相同类型的信息使用相同布局、状态和交互。
- 中文优先：页面文案、错误提示和操作按钮默认使用中文。

## 2. 视觉基调

整体风格采用轻量后台工作台风格：

- 背景使用浅灰白。
- 主操作色使用深绿色。
- 内容区域使用白色面板。
- 辅助文字使用灰色。
- 错误状态使用红色。

当前基础变量定义在 `apps/web/app/globals.css`：

```css
:root {
  --bg: #f7f7f4;
  --panel: #ffffff;
  --text: #202124;
  --muted: #687076;
  --line: #dfe3e6;
  --brand: #126b5b;
  --brand-strong: #0d4f44;
  --danger: #b42318;
}
```

新增页面应优先复用这些变量。确实需要新增颜色时，应先判断是否是通用语义色，例如 warning、info、surface，而不是为单个页面创建一次性颜色。

## 3. 页面结构

标准页面结构：

```text
page
├── page-header
│   ├── page-title
│   └── page-description
└── main content
    ├── panel
    ├── grid-2
    └── stack
```

约定：

- 页面主标题使用 `.page-title`。
- 页面说明使用 `.page-description`。
- 主要内容承载在 `.panel` 中。
- 垂直间距优先使用 `.stack`。
- 双列表单或并列内容优先使用 `.grid-2`。
- 操作区使用 `.actions`，默认右对齐。

不要在普通工具页中增加大面积 hero、渐变背景、装饰图形或营销式说明区。

## 4. 布局规则

- 左侧导航展开宽度保持稳定，当前为 `240px`；收起状态为 `72px`，收起后仍需保留可点击导航入口。
- 主内容区保持足够留白，当前 `.main` 为 `32px`。
- 面板圆角不超过 `8px`。
- 表单控件圆角使用 `6px`。
- 页面内容优先从上到下呈现，不做复杂分栏嵌套。
- 双列布局优先保证桌面端可读性；第一期不要求移动端专门降级布局。

禁止：

- 卡片套卡片。
- 为每个小模块创建不同视觉风格。
- 页面上出现多个争抢注意力的主按钮。
- 使用仅为了装饰的图形、光斑、渐变块。

## 5. 表单规范

表单是本项目第一阶段的主要交互形态。

每个字段应包含：

- 中文 label。
- 必要时提供 placeholder。
- 有约束时提供即时校验或提示。
- 后端错误应转为用户能理解的中文提示。

字段样式：

- 使用 `.field` 包裹。
- label 加粗，字号保持紧凑。
- input、textarea、select 使用统一边框和圆角。
- 长文本输入使用 textarea。

敏感字段规则：

- API Key 使用 `type="password"`。
- 不在页面、URL、localStorage、Markdown 导出中明文展示 API Key。
- 测试接口状态只展示成功、失败、错误原因，不展示密钥。

## 6. 按钮规范

按钮类型：

- `.button`：页面主操作，例如创建项目、保存配置。
- `.button.secondary`：次要操作，例如测试连接、返回、辅助配置。

按钮文案应直接表达动作：

- 推荐：`创建项目`、`保存配置`、`测试连接`、`重新生成`
- 不推荐：`确定`、`提交`、`下一步`，除非上下文非常明确。

状态要求：

- 异步操作中必须禁用按钮。
- 异步按钮文案应显示进行中状态，例如 `保存中...`、`测试中...`、`生成中...`。
- 同一操作不要同时提供多个入口，除非页面信息结构明确需要。

## 7. 状态与反馈

常用状态：

- 成功：使用 `.success`。
- 失败：使用 `.error`。
- 辅助说明：使用 `.hint`。
- 汇总信息：使用 `.summary-box`。

反馈文案应告诉用户发生了什么，以及必要时该怎么修正。

示例：

- `总时长不能超过 240 分钟，请减少集数或单集时长`
- `配置已保存，请测试连接。`
- `请先保存配置`

## 8. 内容工作台规范

后续进入“故事大纲、人物设定、人物示意图、分集大纲、剧本编辑”后，应使用一致的工作台结构：

- 左侧或顶部展示当前项目基础信息。
- 主区域展示当前创作模块。
- 生成结果应可编辑。
- 每个 AI 生成模块应明确展示生成状态、失败原因和重新生成入口。
- 对后续流程有影响的内容，例如故事大纲和人物形象确认，应显示确认状态。

对于 AI 生成内容，不要只显示一段纯文本。应根据内容类型拆分为可扫描结构，例如：

- 故事大纲：背景、主线目标、核心矛盾、起承转合、伏笔、结局方向。
- 人物设定：姓名、身份、目标、关系、性格、视觉描述、示意图。
- 分集大纲：集数、剧情点、钩子、反转、结尾悬念。
- 单集剧本：场次、角色、对白、动作、节奏备注。

## 9. 桌面端布局要求

第一期前端默认面向桌面端工作台，不要求移动端专门适配。

最低要求：

- 页面设计和验收以桌面端为准，建议优先保证 `1280px` 及以上宽度可用。
- 不需要为手机宽度设计独立布局、移动端导航或移动端专属交互。
- 已有窄屏兼容样式可以保留，但不作为新增功能或验收标准。
- 长文本不能挤压关键按钮和表单控件，桌面端固定格式组件应定义稳定尺寸。

如果新增固定格式组件，例如剧本编辑器、人物图卡、分集表格，应优先定义桌面端稳定尺寸，避免内容变化导致布局跳动。

## 10. 前端实现约束

- 不引入新的 UI 框架，除非已有功能明显无法维护。
- 优先复用 `apps/web/app/globals.css` 中的通用类。
- 当某类 UI 在三个以上页面重复出现时，再抽象为组件。
- 组件命名应表达业务或 UI 角色，例如 `PageHeader`、`FormField`、`StatusMessage`。
- 页面代码应保持类型清晰，API 入参和后端 schema 对齐。
- 修改前端后至少运行：

```bash
npm --prefix apps/web run typecheck
```
